# Proof of concept: Postgres + PowerSync

A throwaway system that answers the questions in [Postgres and PowerSync](../docs/postgres-powersync.md#questions-the-proof-of-concept-answers) before the migration. It is deleted once the migration lands.

- `docker-compose.yaml` and `powersync/`: Postgres 17 with logical replication and a PowerSync service, with Sync Streams over a `tasks` table and an `access` table.
- `server/`: one handler, run by Bun (`src/bun.ts`) or as a Worker under `wrangler dev` with Hyperdrive (`src/worker.ts`). It serves Better Auth on Postgres, a PowerSync token, the upload route, a share route that writes `access`, and the PowerSync proxy.
- `web/`: a Vite page with `@powersync/web` and `@powersync/drizzle-driver`, and `e2e.ts`, which drives two devices and a guest in Chromium and WebKit.
- `ios/`: a Swift package with PowerSync and `PowerSyncGRDB`, whose tests answer the iOS questions on macOS and the iOS simulator. See `ios/RESULTS.md`.
- `powersync-cloud/`: the PowerSync Cloud config the cloud run deployed with the PowerSync CLI.

## Run

```sh
cd poc && bun install && docker compose up -d postgres
bun server/src/bun.ts &          # API on 58081, migrates the database
docker compose up -d powersync   # PowerSync on 58080
bunx vite build web --outDir /tmp/poc-web-dist && API=http://127.0.0.1:58081 bunx vite preview web --outDir /tmp/poc-web-dist --host 127.0.0.1 --port 58083 &
bun web/e2e.ts
cd ios && swift test
```

## Results

| #   | Question                                                                                                 | Result                                                                                                                                                                                                                                                                                                                                                                   | Evidence                                                                                 |
| --- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| 1   | Does PowerSync accept a token the server signs?                                                          | VERIFIED. Better Auth's JWT plugin signs EdDSA by default and PowerSync accepts EdDSA, so no RSA setup is needed. The migration signs the token itself with WebCrypto and lists the public key inline, so PowerSync never calls back into the Worker.                                                                                                                    | `probe-auth.ts`: write checkpoint through the proxy answered `200`                       |
| 2   | Do the PowerSync web SDK and the Drizzle driver run in a Vite build in Chromium and WebKit?              | VERIFIED. `worker.format: 'es'` and `optimizeDeps.exclude` are the only Vite settings. The SQLite build adds one 1.1 to 2.5 MB WebAssembly file per page load.                                                                                                                                                                                                           | `web/e2e.ts` in both browsers                                                            |
| 3   | Does the Swift SDK with GRDB build for the simulator, write through records, and observe synced changes? | VERIFIED, with rules. Use `insert`, `updateChanges`, and `delete`; `upsert` throws on PowerSync's views and `save` on a new record silently writes nothing. Open the database with a PowerSync call before the first GRDB query. Upload `opDataTyped`. A `ValueObservation` fires 12 to 19 ms after another client's upload returns. The library builds for watchOS.     | `ios/RESULTS.md`, `swift test` and `xcodebuild test` on an iPhone 17 simulator, iOS 27.0 |
| 4   | Can the Worker forward `/api/powersync/*`, streaming included?                                           | VERIFIED, after one fix. The proxy must ask PowerSync for `accept-encoding: identity` and drop `content-encoding`: Bun decompressed the zstd stream but kept the header, and every browser stream closed after 10 ms.                                                                                                                                                    | `web/e2e.ts` through the Worker under `wrangler dev`                                     |
| 5   | Do Sync Streams over `access` deliver exactly the shared rows and drop them on revoke?                   | VERIFIED. A share reaches the guest in 32 to 42 ms, a revoke removes the rows in 32 to 44 ms.                                                                                                                                                                                                                                                                            | `web/e2e.ts`, `ios` sharing test                                                         |
| 6   | How long does a change take to reach another device?                                                     | Locally 20 to 80 ms. In the cloud (this Mac in Spain, Supabase and PowerSync in us-east-1) 1.9 to 3.5 s, of which the upload request is 1.7 to 3.1 s: the PoC route makes about 10 sequential queries at 190 ms each. Replication and the stream add 0.3 to 0.5 s. The migration keeps upload queries few and runs the Worker with Smart Placement next to the database. | `web/e2e.ts` `uploads` timings                                                           |
| 7   | Does Hyperdrive's `localConnectionString` let `wrangler dev` use local Postgres?                         | VERIFIED                                                                                                                                                                                                                                                                                                                                                                 | `server/wrangler.jsonc`, the e2e run through it                                          |
| 8   | Does the upload route see each write, and does a refused write revert on the device?                     | VERIFIED. PUT carries every column, PATCH only the changed ones, DELETE the id. A refused edit reverts at the next checkpoint, 74 to 218 ms later.                                                                                                                                                                                                                       | `web/e2e.ts`, `ios` record and sharing tests                                             |
| 9   | How much memory does one PowerSync container use?                                                        | About 150 MB idle, next to 60 MB for Postgres, so every worktree can run its own.                                                                                                                                                                                                                                                                                        | `docker stats`                                                                           |

Not settled here: whether PowerSync's replication connection keeps a free Supabase project from pausing after a week without app use. That shows only over time.
