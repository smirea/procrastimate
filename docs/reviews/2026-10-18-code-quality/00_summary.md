# Code quality review, October 18 2026

Commit reviewed: `ad9437e` (master after the Postgres and PowerSync move). Thirteen reviewers each read one slice of the code in full, traced callers, and reproduced what they claimed with scratch tests before writing it down. Their reports are the numbered files beside this one; each names its scope, what it ran, and marks every finding `CONFIRMED` (reproduced or traced end to end) or `PLAUSIBLE` (a strong reading). Scratch scripts under `/tmp` that the reports cite were the reviewers' working files and are not kept.

The fixes this review led to are in the PR that adds this folder. Each finding below says whether it is **fixed** there, **filed** as a task in the `app` project for a later thread, or **noted** as a product question for Stefan.

## Verdict

The codebase is in better shape than its history suggests. The write path, the store rules, the parsers, and the Swift port are compact, well documented, and pinned by tests: 1,500 shared unit tests, the server route tests on PGlite, 30 end-to-end specs, and the vectors that keep iOS in step. Most slices got a "decent" or "good" from their reviewer.

Four things were wrong enough to matter. A guest with an edit share on any project could overwrite any task of the owner's whose id it knew, because a guest `put` on an existing row was checked as a new task. A database blip answered `401`, and both clients sign out on a `401`. Each Ramble session kept its own copy of the day's stored seconds, so sessions opened earlier could stream past the daily cap, which is the cap that bounds what a leaked token costs. And the pre-commit test selector matched file names against string literals, so a change to `server/src/app.ts` ran no tests at all.

The rest is what a codebase accumulates: per-row work that grows with the task list on both clients, a few silent failures where the docs require a toast or a report, duplicated helpers across the three ports, and components that mix a state machine with their markup.

## Correctness and authorization (fixed)

**Guest writes.** `shared/scope.ts` treated a task id with no `access` row as a new task, so a `put` or `patch` on a hidden task passed whenever the write named a project or label the guest could edit. Two reviewers reproduced it independently through `/api/upload` (02 F1, 03 F1). The server now looks up the stored row for every foreign `put`, a `patch` never counts as a create, and a stored task needs an `edit` row whatever the op. The same lookup closes the comment variant, where a guest could rewrite its own comment on a task downgraded to view by naming another editable task in a `put`. Three more guest problems went with it: an agent command that `guestRefusal` partly refused still committed the writes it allowed before answering `403` (03 F2, now all or nothing); a batch was admitted against the `access` rows from before it, so a new subtask's own subtask or comment in the same batch was refused and later reverted on the device (03 F3, now admitted in batch order); and a guest could not undo deleting an imported task because the restore carried a `sourceKey` (03 F4, a guest's key is now dropped rather than refused). `server/src/sharing.test.ts` pins all five.

**Sessions through outages.** `readSession` turned every failure into "no session" (04 F2). It now rethrows anything but Better Auth's own `401`, so a request answers 5xx and the clients keep their session. The web also dropped its sign-out on a `503`, a rule from the first auth commit that no server route produces any more (05 F3), and iOS signed out on any non-200 answer or non-JSON body, which a captive portal's page triggers (12 F1). Both clients now sign out only on a `401` or a session with no user.

**Ramble's daily cap.** Each session copied `storedToday` when it opened and never saw what sessions that closed afterwards had stored (04 F1). The reviewer's scratch test streamed twice the cap. The day is now one shared count per user that every session charges, the cap is checked before the space is read, and `server/src/ramble.test.ts` drives the real route with a fake upstream to pin both caps; the session code had no tests since its spec was deleted in `4d5e059`.

**Smaller confirmed bugs, all fixed.** Completing a task on an event series on the server read each occurrence's day in the Worker's UTC zone, so the agent API skipped the wrong occurrence for part of every day (02 F2). `feb 29` typed outside a leap year stayed text (01 F3). An unclosed quote in a Todoist CSV folded the rest of the file into one task with no warning (01 F2). Ramble built a titleless root's subtasks twice and emitted every token twice (01 F5). The iOS Ramble turned emoji into U+FFFD by copying one UTF-16 unit at a time into a `String` (10 F1). The value schemas accepted unsorted weekday sets, which stepped to the wrong day, and dates like `2026-02-31` (02 F3). On the web, Escape in the four inline rename fields saved the cancelled edit in Chromium and Enter saved twice (07 F1); task details kept a stale title and wrote it back over a remote rename (06 F1), and iOS committed an untouched title on every close with the same effect (13 F1); a local write the database refused was never read back (05 F1); push subscriptions survived sign-out (05 F2); a failed audio graph left the microphone recording (05 F4); a drag committed an index the sync had moved (05 F7); a task deleted elsewhere left the sheet state open with nothing shown (07 F2); the public link page blamed every failure on the owner (07 F3); the iOS connector uploaded images after reading the batch's edits (12 F2); and a ramble started in a shared project showed no project or label tokens (13 F7). The backup read each table in its own snapshot (04 F3), and malformed VAPID or PowerSync keys passed config to fail at first use (04 F4).

## Efficiency (mostly fixed)

Search folded text one character at a time as soon as a field had one accented character, and folded each task twice per keystroke; at 3,000 tasks that was 17 to 38 ms per keystroke against 1.5 to 6.7 ms for ASCII (01 F1). On iOS the same path cost 608 ms per keystroke for 5,000 tasks with smart quotes (10 F2). Both now fold ASCII characters directly inside the loop and each field once; the web case measures about 8 ms. `wallTime` built an `Intl.DateTimeFormat` per call, which made server push planning twenty times slower than it needed to be (02 F4). `descendantsOf` rebuilt the child index per root, so a project screen with sections paid 12 ms per store change at 2,000 tasks (02 F5). `rowWrites` deep-compared entities the rule had passed through unchanged (02 F6). The web store derived every list from one signal, so a command on the tasks reran everything that read labels, sections, or comments (05 F6); it now derives one per list. Every task row mounted a popover with four window listeners (06 F4); popovers now listen only while open. The waveform redrew at 60 fps through the whole review phase (06 F5). `View` built the Markdown document on every render to read its title (07 F6). The sidebar and the iOS Browse screen sorted every project's and label's list just to count it (07 F7, 13 F4); one pass now counts them. The iOS Ramble compiled 26 regexes on every transcript update (10 F4).

**Filed.** The iOS `Store` has no indexes, so each visible row scans every task and comment on every change (11 F1, 13 F3). A 1,000-write upload runs 1,000 single-row statements where one multi-row upsert per kind would do (03 F6). Spotlight rebuilds its whole index before its debounce (12 F4), and `CalendarSync` runs one calendar query per event task on the main actor (12 F8). The web `writeRows` runs one `SELECT` per put (05 F9), and the Views sort functions recompute keys inside the comparator (11 F6).

## Robustness (mostly fixed)

Three silent failures on iOS now report or toast: a failed place lookup, a photo that fails to load, and the place monitor's event loop ending (12 F9, 13 F6). A local write that fails on iOS tells the user instead of only Sentry (12 F5), and an entity that does not encode stops the command instead of becoming "no change" (11 F2). The Todoist import on the web reports a store failure as its own rather than "not a Todoist zip" (06 F3). The Keychain token is readable after the first unlock, so a background relaunch on a locked phone no longer lands on sign-in offline (12 F6). `worktree-gc` read a failed `git worktree list` as "no worktrees", which from outside a checkout would have deleted every agent's simulators, containers, and databases (08 F2). `pr-ship` reported any `gh` failure as "no PR" (08 F10). A master push whose deploy was skipped showed green (08 F9). The advisory lock tests skipped locally and in CI (09 F1); the e2e job now runs them. The Swift generator refuses names that are not identifiers and enforces string lengths (08 F3, in part).

**Filed.** The Ramble global budget leaks on eviction and idle sessions can hold all of it (04 F8). `POST /api/push/test` accepts any https URL (04 notes). The web has no offline shell, so a cold launch offline fails although the docs promise it opens (05 F8). Two copies of the iOS notification scheduler can interleave (12 F3). The Swift generator still drops unknown keywords and falls back to `JSONValue` silently (08 F3, the rest).

## Simplification

**Fixed.** The contract's worker and space halves were a leftover re-merged by hand (03 F7). The agent commands read a task back twice (03 F9). Ramble had its own priority grammar beside quick add's (01 F4). The dead `startVoiceInput` and its test, which pinned the opposite of production's fallback, are gone (05 F5). Four hand-rolled inline inputs are one `InlineEdit` component. The pre-commit selector walks the import graph (08 F1, 09 F3). Six shared test files reuse the shared task factory (09 F8), each test app clones one migrated PGlite instead of migrating again (09 F10), two e2e specs stop repeating vectors (09 F6), and three unused dependencies and three dead iOS scripts are gone (08 F6, F7).

**Filed.** The biggest structural items are on iOS: six picker chips copy one shell, the shared `Chip` is a 32 pt target, quick add's pick rules live in the view instead of `QuickAddDraft`, and `RambleDrawer` and `QuickAddSheet` mix a state machine, editing helpers, and app-wide components (13 F5, F8, F9, F10); `moveOrders`, the creation comparator, and the "replace by id" map are each written several times in Core (11 F3 to F5), and three JS-to-ICU regex layers should be one (10 F3). On the web, QuickAdd's draft model is 200 lines of untested logic in a component whose merge rules are copied in TaskDetails and `rambleNewTask` (06 F6), five sheets copy the same shell (06 F7), and the project, label, and section headers copy the same actions popover (07 F4). In shared, the snapshot, store, and model files restate shapes and comparators (02 F8), and quick add recognizes a date with one grammar then re-parses it with another (01 F6). The scripts repeat their process and dotenv helpers about eight times (08 F5).

**Noted as product questions.** Whether the web should refuse duplicate project and label names as the agent API does (03 F8). Whether a guest may move the owner's task into the owner's Inbox (02 notes). Whether a public link should return task locations, event data, and user ids (03 notes). Whether the ElevenLabs path should be limited to an allow-listed account while sign-up is open (04 F8). Whether the `testflight-processed` workflow is still wanted (08 F7). Whether the project and section delete prompts should count the same way (07 notes).

## Test coverage

The unit suites test behavior with literal expectations, and the vector mechanism is justified: Bun exposes no current test name, so the wrappers are needed (09). The gaps the reviewers found, with what this PR adds in parentheses: guest writes on existing rows (five sharing tests), the Ramble server caps (two session tests), a database failure during a session read (one actor test), event-series completion in a zone (one subtasks vector), the schema refinements (two task tests), the leap day and CSV cases (vectors), duplicate Ramble tokens over the whole corpus and an emoji title (two ramble tests), the open counts (one views vector), Escape on an inline rename (sections e2e), and `NativeDictation` (five unit tests). Still open: the Ramble idle end and midnight split, a remote change while details are open on the web, the iOS App target, which has no tests, and the memo-tasks rule for a resend after an app-side delete now that the test that claimed to cover it is fixed.

## Remediation sequence

The PR lands the fixes above in six commits, one per area, each green on its own tests. The filed work is ordered by what it buys: the iOS store indexes and the chip shell first, since they change what the phone does on every tap; then the web QuickAdd draft extraction, which unlocks unit tests for the most intricate client logic; then the server batch upsert, which only matters for imports and long offline stretches; then the dedupe passes, which are safe to do slice by slice with the vectors as the acceptance test.
