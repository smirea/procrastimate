# Sync build slices

How sync gets built, one PR per slice, each off `master`, never stacked. The design is in [Sync](decisions/sync.md). iOS slices `S1` to `S8` are in [iOS parity](ios-parity.md#thread-split). A slice starts once the slices it depends on have merged. Each slice edits only the files it owns, plus its own rows in the feature map and docs.

| Slice | Thread | Depends on | Runs in parallel with |
| --- | --- | --- | --- |
| Y1 | Sync core in `shared/sync/` | — | Y2, S1, S2 |
| Y2 | `Account` Durable Object and auth | — | Y1, S1, S2 |
| Y3 | `POST /api/sync` | Y1, Y2 | S2 to S8 |
| Y4 | Web sync client | Y3, S2 | S3 to S8 |
| Y5 | Server-computed Web Push | Y4 | S3 to S8 |
| Y6 | Realtime nudge | Y5 | S3 to S9 |
| S9 | iOS sync client | Y3, Y4, S8 | Y5, Y6 |

Y1 and Y2 can start as soon as the sync design merges. They share no files with each other or with S1 and S2.

- **Y1: Sync core.** Pure TypeScript in new files under `shared/sync/` only: the HLC (`hlc.ts`), op, change, and request and response zod schemas with per-kind field schemas for tasks, projects, labels, and settings (`protocol.ts`), the snapshot diff that turns a before and after snapshot into ops (`diff.ts`), the client's `applyChanges` with outbox replay (`apply.ts`), the server's `applyOps` with per-field last-writer-wins, op-id dedupe, tombstones, and future-clock clamping (`merge.ts`), `fixups` for orphans, open-under-completed, root project, deleted labels and projects, name merges, and source-key merges (`fixups.ts`), and the fractional order helper (`order.ts`). Unit tests for every rule in [Sync](decisions/sync.md#conflicts), plus `converge.test.ts`, the seeded two-to-three-client fuzz that drives random snapshot edits through `diff` and asserts convergence and the invariants. Owns `shared/sync/**`. Depends on nothing.
- **Y2: `Account` Durable Object and auth.** The SQLite-backed `Account` class in `server/src/account/` with the `entities`, `log`, `devices`, and `pairing` tables behind a small storage interface, with a SQLite implementation for the Worker and an in-memory one for the Bun dev server. `server/src/auth.ts` holds `authenticate(request) → deviceId | null`, setup with `SYNC_SETUP_CODE`, pairing codes (eight characters, ten minutes, five attempts), SHA-256 token hashes, the device list, and revoke. Routes: `POST /api/auth/setup`, `POST /api/auth/pair`, `POST /api/auth/redeem`, `GET /api/auth/devices`, `DELETE /api/auth/devices`. Owns `server/src/account/**`, `server/src/auth.ts`, the route and export lines in `server/src/api.ts`, `server/src/index.ts`, the `Env` type, the `ACCOUNT` binding and `v2` migration in `wrangler.jsonc`, and the `SYNC_SETUP_CODE` entry in the env-manager schema for local dev. Depends on nothing.
- **Y3: `POST /api/sync`.** Wires Y1's `applyOps` and `fixups` into the `Account` object: authenticate, apply ops in one storage transaction, append the winning fields to `log`, return `acked`, `changes` after the cursor, the new cursor, and the server HLC, or the full snapshot for cursor `0`. Server tests for idempotent retries, cursor paging, the snapshot path, and a two-device first sync that merges a shared Todoist import. Owns `server/src/account/sync.ts` and its route line. Depends on Y1 and Y2.
- **Y4: Web sync client.** `app-web/src/lib/sync.svelte.ts` runs the loop (launch, focus, online, one second after a commit, every minute while visible) and exposes a status. The store writes the `sync` section (device id, cursor, outbox), whose shape S2 put in `shared/snapshot.ts` with a loose op schema that Y4 replaces with Y1's, and the token goes under its own `procrastimate-device` key. `store.svelte.ts` diffs on commit into the outbox while paired and applies pulled changes. The shared store rules already keep tasks sorted by `createdAt` then `id`. `moveSubtask` in `shared/subtasks.ts` writes one fractional `order`, with `id` as the last tie-break. Settings gains a Sync section: set up with the setup code, `Pair a device` with the code, enter a code, the device list with `Remove`, and the status. A Playwright spec with two browser contexts against the dev server's in-memory account covers propagate, offline, reconnect, and conflict. Owns those files, the Settings component, `app-web/e2e/sync.e2e.ts`, and the feature map's `offline-sync.md` and `settings.md`. Depends on Y3, and on S2 because both edit `store.svelte.ts`.
- **Y5: Server-computed Web Push.** The `Account` object recomputes every pending notification after each push from synced state, in the account's `timeZone`, with the notification text S2 moved to `shared/`, and arms one alarm. Subscriptions register under the device token, and the Notifications panel asks an unpaired device to turn on sync first. Adds `shared/zoned-time.ts`. Removes `PushSchedule`, `PUT /api/push/schedule`, and the client's schedule upload, with a `deleted_classes` migration. Owns `server/src/account/push.ts`, `server/src/push.ts`, `server/src/push-schedule.ts`, `app-web/src/lib/push.svelte.ts`, `app-web/src/lib/push-schedule.ts`, [Push notifications](decisions/push-notifications.md), and the feature map's `push-notifications.md`. Depends on Y4.
- **Y6: Realtime nudge.** A hibernating WebSocket on the `Account` object that sends the new cursor after every applied push, and the web client syncs when it hears one, reconnecting with backoff. Owns `server/src/account/realtime.ts`, its hook in the object, and the socket part of `sync.svelte.ts`. Optional. Depends on Y5 because both edit the object.
- **S9: iOS sync client.** Adds `recorded('sync', …)` wrappers to the HLC, `diff`, and `applyChanges` tests and commits `shared/vectors/sync.json`. Ports them to `Core` with `VectorTests`. In `App`: the Keychain token, a `URLSession` client for `/api/sync` and `/api/auth/*`, the same triggers plus the `BGAppRefreshTask`, local notifications recomputed after each pull, and the Sync section in Settings. Updates the `sync-*` rows in [iOS parity](ios-parity.md). Depends on Y3, Y4, and S8.
