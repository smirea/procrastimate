# Visual language

- **Liquid Glass, not Todoist.** The look follows Apple's Liquid Glass (iOS 26) so the web app and the native app match. Keep these consistent with native iOS:
  - **Layering.** Content sits on a solid base layer and stays readable there. Glass is only for floating chrome above it: the sidebar and drawer, quick add, task details, search, popovers, toolbars, toasts, and the add button. Glass never nests in glass. Controls inside a glass layer use quiet fills.
  - **Materials.** `.glass` is the regular material for chrome over the canvas. `.glass-strong` is denser, for layers that carry text over moving content (sheets, popovers, the drawer). Both are a translucent fill, a blurred and saturated backdrop, and an inset specular rim: a bright top edge, a dim bottom edge, and a hairline ring.
  - **Mostly opaque.** Stefan wants surfaces to read as solid, so the fill does most of the work and the blur adds depth at the edges. The regular material is 72% opaque and the dense one 94%, in both themes. The blur stays.
  - **Literal blur values.** Each material writes its `backdrop-filter` out in full. The production CSS minifier keeps only the `-webkit-` copy of a `backdrop-filter` that uses `var()`, and Chromium ignores that copy.
  - **Shapes.** Buttons and chips are capsules. Corners are concentric, so an inner radius is the outer radius minus the padding between them. `--radius-popover`, `--radius-panel`, and `--radius-sheet` set the outer radii.
  - **Motion.** Sheets and popovers grow from their source and settle with spring easing. Pressed controls shrink slightly on a spring (`.press`, and built into `.chip`, `.btn`, `.icon-btn`, `.menu-item`). Lists reflow with animated position changes.
  - **Spacing.** Use a 4 pt grid and touch-sized hit targets (at least 32 px with a mouse, 44 px on touch, 44 pt on iOS). `.icon-btn` is 36 px with a mouse and 44 px on touch.
  - **Controls.** Use controls with direct native counterparts: list rows with leading checkboxes, a sidebar that maps to a tab bar or split view, sheets for creation and details, menus for pickers, and toasts for undo. Avoid web-only patterns such as hover-only actions and multi-level dropdowns.
- **Accessibility fallbacks.** Under `prefers-reduced-transparency` or `prefers-contrast: more`, glass becomes an opaque `--glass-solid` layer with a stronger outline and no backdrop filter. iOS Safari reports Increase Contrast as `prefers-contrast: more`.
- **Rendering: layered CSS, no refraction.** Real Liquid Glass bends the content at its edges. The web can only do that with an SVG `feDisplacementMap` in `backdrop-filter: url()`, which only Chromium renders. WebKit drops SVG filters in `backdrop-filter` ([WebKit bug 245510](https://bugs.webkit.org/show_bug.cgi?id=245510)), and every iPhone browser is WebKit. So the material is CSS only: `backdrop-filter: blur() saturate()` plus inset rim shadows. It has no runtime, no dependency, and no per-element filter.
  - **Prototype.** A throwaway app shell compared a CSS-only variant with one that adds Chromium SVG refraction. Its screenshots are in the pull request that added this section. On iPhone-size WebKit the two render the same. In desktop Chromium the refraction is visible only at the edges, and it needs a lighter blur that lets list text show through the sheet.
  - **Libraries considered.** None renders refraction over ordinary page content on iPhone. [liquidglass.dev](https://liquidglass.dev/) (about 30 KB gzipped) refracts in Safari only over images marked as the backdrop and falls back to frosted blur over DOM, which is every surface here. [liquid-svelte](https://github.com/quentin-r37/liquid-svelte) (Svelte 5, needs `motion`, not on npm) and `@lollipopkit/liquid-glass-svelte` (MIT) use displacement maps that need Chromium's `backdrop-filter: url()`, and they would replace our components. `liquid-glass-svelte` (MIT, about 12 KB, untouched since June 2025) is a CSS blur wrapper, no better than our own classes. `liquid-glass-react` (MIT) is React and Chromium only. liquidcn copies in bits-ui components with CSS glass and would add a component framework for a look we already have.
  - **Revisit when WebKit ships `backdrop-filter: url()`.** [WebKit PR 68614](https://github.com/WebKit/WebKit/pull/68614) implements it. Until Safari renders it, refraction would be a desktop-only extra that diverges from the phone.
