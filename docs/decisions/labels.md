# Labels UI

- **Rows.** A row's title shows up to two lines, and its labels follow the title inline as small chips in each label's color, Todoist style. When the title and labels need more than two lines, the title takes the ellipsis and the labels stay visible at the end of the second line, since they say where a task is filed. The date, repeat, reminders, and the rest stay on the line below. Search results show the labels that matched the same way. The web measures each row once when its title, labels, or width change and floats the chips to the end of line two; iOS draws the chips inside one `Text` with a `TextRenderer` and truncates the middle of the last line, so the ellipsis lands in the title.
- **Colors.** Every label has a synced `color`, a key into twelve colors: red, orange, amber, lime, green, teal, cyan, blue, indigo, violet, pink, and gray. `LABEL_COLORS` in `shared/label-colors.ts` lists the keys, and `app-web/src/index.css` holds each color's light and dark values as `--label-<key>` (text and the tag glyph) and `--label-<key>-fill` (the chip), next to every other theme token, so the contrast test holds the text to AA on its fill over every surface, and iOS generates the same colors. The values are Tailwind's hues, darkened in light mode and lightened in dark mode just enough to pass. One chip component per client draws a label in its color: `LabelChip.svelte` and `LabelChip` in `TaskRow.swift`. Quick add chips, the details picker, search, the sidebar or Browse, and the label view's heading use the same color. The quick add parser's `@name` highlight stays one neutral label tint, since it marks a phrase rather than a label.
- **Default color.** A new label takes `defaultLabelColor(name)`, ported to `LabelColors.defaultLabelColor`. A word with an obvious color picks it (`bug` or `urgent` red, `waiting` amber, `calls` or `work` blue, `health` or `money` green, `deep` indigo, and a few more). The first hinted word wins, so `deep work` is indigo. Every name `LabelColors.modelInstructions` lists that a hint also knows takes the prompt's color, so a label named that on iOS doesn't switch color a second after it is created; `LabelColorsTests` parses the prompt and checks. Any other name hashes (FNV-1a over UTF-16 code units of the lowercased name) to one of the eleven colors besides gray, so every client picks the same color offline. A label synced or stored before colors existed takes the same default, on the server and when a client loads its stored document.
- **Sidebar.** A Labels section below Projects lists every label alphabetically with its open task count. It appears once a label exists, because labels are created inline, so an empty section would only add clutter.
- **Details picker.** A `Labels` chip on its own row under the title opens a menu with a filter field and the labels in autocomplete order, each with a check. A tap toggles a label and keeps the menu open, unlike single-value pickers, since a task often takes several labels. Enter toggles the highlighted row or creates the typed label. The field takes focus on desktop only, so a phone keeps its keyboard down until the field is tapped. The row sits outside the details body because the body scrolls while the keyboard is up, and a scroll container clips popovers.
- **Quick add.** No label picker, since `@` covers it and one more chip wraps the chip row on a phone. Typed labels and a label view's default label show as chips. An `@name` that names no label shows a `Create @name` chip that creates it on tap, as Quick add and natural language describes.
- **The on-device model picks a new label's color on iOS.** Creating a label stays instant and offline: it starts with `defaultLabelColor`, and then `LabelColorModel` asks Apple's Foundation Models for the palette color that fits the name, with guided generation limited to the twelve keys and `LabelColors.modelInstructions` giving each color its usual meanings. The answer is applied as an ordinary color edit, so it syncs, unless the label was renamed, recolored, or deleted meanwhile (`StoreRules.suggestLabelColor`). An unavailable model (an unsupported device, Apple Intelligence off, the simulator), an error, or no answer within 5 seconds leaves the default. On a Mac the model answers in about half a second. Only labels created by hand ask the model: a label decoded from storage or the server, and a Todoist import, keep the default, because those names were not just typed, an import could create dozens at once, and the user did not just pick them. Sections have no color, so they have nothing to pick. The web keeps the deterministic default; see [iOS-only features](ios.md#ios-only-features).
- **The color model has an eval.** `app-ios/Evals/LabelColorModel` holds 32 label names, each with the colors a person would accept (`taxes` green or red, `hiking` lime, green, or teal), and scores the model on the Mac like the Ramble eval, to catch drift when the prompt or the OS model changes. October 2026, macOS 27: the model passes 31 of 32 (median 0.4 s; it calls `weekly review` violet), and `defaultLabelColor` passes 12, so the prompt stayed as it was. After the `deep` and `creative` hints made the default agree with the prompt, the default passes 13 and the model still 31.
- **Label actions.** A label view's header picks the label's color, renames it, or deletes it. The web popover starts with a 6 by 2 grid of swatches, a `Label color` radio group that stays open so the heading and chips recolor in place. iOS puts the same colors in a `Color` submenu of the `Label actions` menu, above `Rename`, each a named swatch with a check on the current one. A palette row was tried first, but twelve swatches scroll sideways in a menu and VoiceOver could not name them. Delete confirms and keeps the tasks. Label names are unique ignoring case, because `@name` must resolve to one label, so a rename onto another label's name is ignored.
- **Punctuation ends a fragment.** A `#` or `@` fragment ending in `,`, `.`, `;`, `:`, `!`, `?`, or `)` closes its list, matching the parser, so `Call @calls,` plus Enter saves instead of offering to create `calls,`.
- **Search.** Search matches label names and lists labels as their own group. See Search.
