# Dev hosting

- **Local dev runs on Docker.** `docker/compose.yaml` has two services. `postgres` is one Postgres 17 container for every worktree (`procrastimate-postgres`, `127.0.0.1:5440`, `wal_level=logical`, a named volume), each worktree in its own database named after its branch. `powersync` is `journeyapps/powersync-service:1.27.0`, one container per worktree on a port from the worktree's block, with its storage in a second database next to the worktree's. Both join the `procrastimate` Docker network, so PowerSync reaches Postgres by container name on macOS and Linux alike. Nobody runs `docker compose` by hand: `scripts/local-stack.ts` does, for the worktree scripts and CI.
- **`scripts/setup-worktree.ts` provisions a worktree.** It fails in a second with the fix named when Docker is down, picks the worktree's port block, creates its database, writes `.powersync/service.yaml` from `powersync/local/service.template.yaml`, starts one PowerSync container, and writes `.env.override`: `CLIENT_PORT`, `API_PORT`, `API_URL`, `DATABASE_URL`, and `POWERSYNC_URL`. A block holds web, API, and PowerSync at `+0`, `+1`, `+2`, and the e2e web and API at `+10` and `+11`. The end to end suite shares the database and PowerSync with `bun run start`: each test signs up its own users, so sharing costs only those users piling up in the dev database, where a second database and container per worktree cost a second set of everything to provision, migrate, and clean up. `--reset-db` drops and recreates the databases, which is how a worktree recovers from a rewritten migration. `scripts/teardown-worktree.ts` removes the containers and drops the databases, and `scripts/worktree-gc.ts` does the same for worktrees that no longer exist, finding them by the worktree path each container carries as a label and each database as a comment.
- **The Bun dev server needs no cloud.** `bun run start:server` migrates the worktree's database, then serves `server/src/api.ts` with Ramble's socket on Bun's WebSocket server. Values env-manager leaves empty get local stand-ins: the committed dev PowerSync key, a fixed auth secret, no sign-in rate limit, and a fresh VAPID pair per start. `bun scripts/sync-smoke.ts` proves the whole loop against it (see [Sync](sync.md#testing)).
- **One origin for the browser.** The web client's server always proxies the backend, so the browser talks to exactly one origin: `/api/*` to the API, which forwards `/api/powersync/*` to PowerSync. Browser code calls relative `/api` paths. `API_URL` and any other host or port stay in Vite's Node-side proxy config and never reach the client through `import.meta.env`, a `PUBLIC_` variable, or the bundle. This holds everywhere, including local dev, the e2e suite, and the box.
- **No third-party origins.** The browser fetches nothing cross-origin. Fonts and other assets ship from the app's own origin, so Google Sans Flex (SIL OFL 1.1) is self-hosted from `@fontsource-variable/google-sans-flex`. The `single-origin` e2e test fails on any request that leaves the page's origin.
- **Stefan's dev web client runs on potatoey's box.** Stefan opens it over HTTPS at `https://stf-box.tailff2195.ts.net:6120`. ProcrastiMate owns ports 6120 (web) and 6121 (API) there. `tailscale serve` terminates TLS on 6120 and proxies to the Vite dev server on box-local port 16120. The box's server runs against the dev Supabase and PowerSync from env-manager `dev`, not Docker.
- **The box tracks `master`.** Its checkout auto-pulls about every 3 minutes, so every merge is live within minutes.
- **The box starts the client with `--host $HOST --port $PORT` and `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS=.ts.net`.** Keep the web client compatible with that launch. Vite CLI flags must keep overriding the config's host and port, `server.allowedHosts` must stay an array, and the `/api` proxy must keep working through any allowed host. `.ts.net` admits `stf-box.<tailnet>.ts.net`.
- **Don't depend on a secure context.** Local runs and tests still use plain HTTP, so browser APIs limited to secure contexts, such as `crypto.randomUUID`, need a fallback.
