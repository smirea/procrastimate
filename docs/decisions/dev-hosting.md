# Dev hosting

- **Local dev needs no service.** Everything has to run on a Mac with no cloud account, worktrees side by side without sharing state, and CI has no AWS access. The Bun dev server keeps the whole database in one SQLite file, `.data/<worktree directory>.sqlite`, git-ignored, so each checkout has its own and nothing is shared. There is no Docker, Postgres, or sync service to start. `PROCRASTIMATE_DATABASE` names another file or `:memory:`, which the end to end suite uses, and `PROCRASTIMATE_RESTORE` loads a dump into a database that holds no user yet, as a production backup or the Postgres import ([Persistence](persistence.md)).
- **`scripts/setup-worktree.ts` provisions a worktree.** It picks the worktree's port block, writes `.env.override` (`CLIENT_PORT`, `API_PORT`, `API_URL`), runs `env-manager gen --local` and `bun run generate`, and writes `./sim`. Each app made by setup-new-app owns a 10-port slot at its main `CLIENT_PORT` (6000, 6010, 6020, and so on; ProcrastiMate's is 6120 to 6129). Worktree n gets the same layout at `main + 10000 + (n - 1) * 1000`: 16120 for the first, 17120 for the second. Worktrees of different apps never collide, because main ports are 10 apart and worktrees step by 1000, and n stops at 33 to stay below macOS's ephemeral ports at 49152. A block holds web and API at `+0` and `+1`, and the e2e web and API at `+5` and `+6`, all inside the app's slot, since `+10` is the next app's. `scripts/ports.mts` holds the layout and reads the main port from the root `.env` default. A rerun keeps the worktree's number, and moves a worktree from the old 6200 to 6980 blocks into the new scheme. `--reset-db` deletes the worktree's database file. `scripts/teardown-worktree.ts` removes the worktree, its file with it, and `scripts/worktree-gc.ts` frees simulators and DerivedData. The Docker Postgres and PowerSync containers of the old stack are no longer managed; remove them once with `docker rm -f` if a Mac still has them.
- **The Bun dev server is the Worker's handler on one SQLite file.** `bun run start:server` opens the file, migrates it the way the `App` object does ([Persistence](persistence.md)), and serves `server/src/api.ts` with the sync socket and Ramble's socket on Bun's WebSocket server. Values env-manager leaves empty get local stand-ins: a fixed auth secret, no sign-in rate limit, and a fresh VAPID pair per start.
- **Local SQLite refuses what a Durable Object would.** A Durable Object binds at most 100 parameters per statement, so the Bun store's Drizzle logger and engine driver throw past 100, and `IN` lists over ids run in parts (`server/src/db/chunks.ts`). Its SQLite also refuses a compound `SELECT` of many terms, which `bun:sqlite` allows; that one only the Worker build catches, which is why CI runs the end to end suite against `wrangler dev`.
- **One origin for the browser.** The web client's server always proxies the backend, so the browser talks to exactly one origin: `/api/*` to the API, sync and its live socket included. Browser code calls relative `/api` paths. `API_URL` and any other host or port stay in Vite's Node-side proxy config and never reach the client through `import.meta.env`, a `PUBLIC_` variable, or the bundle. This holds everywhere, including local dev, the e2e suite, and the box.
- **No third-party origins.** The browser fetches nothing cross-origin. Fonts and other assets ship from the app's own origin, so Google Sans Flex (SIL OFL 1.1) is self-hosted from `@fontsource-variable/google-sans-flex`. The `single-origin` e2e test fails on any request that leaves the page's origin.
- **Stefan's dev web client runs on potatoey's box.** Stefan opens it over HTTPS at `https://stf-box.tailff2195.ts.net:6120`. ProcrastiMate owns ports 6120 (web) and 6121 (API) there. `tailscale serve` terminates TLS on 6120 and proxies to the Vite dev server on box-local port 16120. The box's server keeps its own SQLite file like any checkout.
- **The box tracks `master`.** Its checkout auto-pulls about every 3 minutes, so every merge is live within minutes.
- **The box starts the client with `--host $HOST --port $PORT` and `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS=.ts.net`.** Keep the web client compatible with that launch. Vite CLI flags must keep overriding the config's host and port, `server.allowedHosts` must stay an array, and the `/api` proxy must keep working through any allowed host. `.ts.net` admits `stf-box.<tailnet>.ts.net`.
- **Don't depend on a secure context.** Local runs and tests still use plain HTTP, so browser APIs limited to secure contexts, such as `crypto.randomUUID`, need a fallback.
