# Feedback

Feedback (`github.com/smirea/feedback-engine`, the owner's own package) freezes a screen into an editor where a tap picks a component and a note says what should change. It exports an annotated image and a JSON report naming each component's `file:line` and data, so an agent can act on it without guessing, and its Share menu posts both to ProcrastiMate as a task. Both clients run it in every build, including production, since Stefan is the only user. iOS's setup is in [iOS app](ios.md).

- **Always the latest web package.** `app-web` depends on `@stefan.inc/feedback-engine` at `latest`, never a range. The lockfile alone would freeze it, so CI's setup action runs `bun update --filter app-web @stefan.inc/feedback-engine` after the frozen install, and every build and deploy takes the newest release. Locally the lockfile's version runs until someone updates it. iOS names the repository's `master` branch, but `Package.resolved` pins one commit of it, and Xcode and CI build that commit until someone bumps the pin: nothing does that automatically, so a change that needs a newer engine bumps it in the same PR.
- **Opening it on the web.** Alt+Meta+click (Option+Command+click) on anything captures the page with that element selected. A phone has no modifier keys and no shake on the web, so three fingers held still anywhere for 600 ms capture the screen under them at once (`holdThreeFingers` in `app-web/src/lib/feedback.ts`). One finger already holds for the row menu and project reorder, and two pinch, so three is the first count that takes nothing away. Settings also has **Give feedback**, for when the gesture is not at hand: it closes Settings and counts down 5 seconds, so the screen behind it, or the one opened in time, is what gets captured. There is no floating button, which would cover the quick add button and every screen.
- **Signed in only.** `startFeedback()` in `app-web/src/lib/feedback.ts` runs from the root layout while the session is in, and not on a public link page, whose visitor has no session to post with.
- **Posting to this origin.** The web package's ProcrastiMate entry is given `url: ''`, so it calls this origin's own `/api/view`, `/api/images`, and `/api/tasks` with the session cookie, the same routes AI accounts use. It needs no token and none of the package's dev proxy, and works the same in development, previews, and production. The toast links to the task on the same origin.
- **GitHub issues, from Stefan's account only.** Both clients add feedback-engine's webhook entry **GitHub Issue** to the Share menu, after ProcrastiMate. It posts the image and `feedback.json` as multipart to `POST /api/feedback/issues`, a contract procedure, and the server files them as an issue labeled `feedback` in `smirea/procrastimate` (`server/src/feedback-issues.ts`, ported from the package's `examples/github-webhook`). The account is the gate, not a webhook key: only the user whose Better Auth id is the server's `FEEDBACK_GITHUB_USER_ID` (Stefan's, `Q9DhfYbBj3Um6gh3v1L7ZfaJJvQkvjev` in `prod`) may post, a personal token of his counts as him, and anyone else, AI accounts included, gets `FORBIDDEN` before GitHub hears of it. The clients ask `GET /api/feedback/github` once per sign-in and show the entry only when it answers `enabled`, so no one else sees it. The web posts to its own origin with the session cookie; iOS sends the session token as its bearer, read when the post is made. Issues are opened by the `smirea-ai` account, whose `gh auth token --user smirea-ai` is `FEEDBACK_GITHUB_TOKEN`, so they stand apart from Stefan's own. It is a separate token from `GITHUB_TOKEN`, which only reads issues for task chips and stays read only. The token is a `gh` login's, so logging `smirea-ai` in again rotates it: set the new one in env-manager `prod` and run `bun run secrets:push`. `dev` leaves both unset, since a local database's ids are not Stefan's, so a local run has no entry; set both in a local run to try it.
- **The report's context.** Both clients attach `Session` (API, signed in, user), `Sync` (online, live, pending writes, last error, refused writes), `Navigation` (route and sheet), and `Store` (row counts).
- **Tag every named region.** Every screen, sheet, popover, and repeated row or card ends up tagged, as on iOS. On the web that is `{@attach feedback()}` on the component's root element, with the Vite preprocessor in `vite.config.ts` writing in the name and `file:line`. `Sheet` and `Popover` spread their rest props onto their root element, so a component whose root is one of them tags it in place (`<Sheet {@attach feedback()} …>`). `Popover` also tags its open panel as `Popover` with its label. `View`, the shell every list screen renders, reports its name and filter rather than its task arrays. Single buttons, chips, fields, and icons stay untagged, since the DOM already gives them roles and names.
- **The editor ships in the main bundle.** The tags import the same `/svelte` entry as `setupFeedbackEngine`, so a dynamic import of the setup cannot split the editor out: it adds about 38 kB gzipped to the shared chunk every page loads. Splitting it needs the package itself to load its editor on first use.
