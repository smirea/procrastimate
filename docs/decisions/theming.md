# Theming

- **System, Light, and Dark.** `System` is the default and follows `prefers-color-scheme` live. `Light` and `Dark` override it. These are the same three choices iOS offers, so the native app maps one to one.
- **A device preference, not task data.** The choice lives in its own `localStorage` key (`procrastimate-theme`), outside the task store, so it never syncs. `System` stores nothing.
- **A theme color, also a device preference.** Settings offers nine theme colors (`Frost`, a frosty vibrant blue, by default, then Indigo, Violet, Pink, Red, Amber, Green, Teal, and Graphite). A rainbow `Custom` swatch is the tenth cell, so the picker is exactly two rows of five; it opens the platform's own color picker (`<input type="color">` on the web, `ColorPicker` on iOS) for any other color, and once picked it fills with that color and shows the check. Orange was dropped to make room, since it sat next to Red; a saved `orange` parses as unknown and falls back to Frost. The choice lives in `procrastimate-accent` next to the theme, outside the synced settings record: it is a look, like the theme, it needs no migration, and the pre-paint script can read it before the database opens. The value is a preset's key or a custom color's `#rrggbb` base in lowercase (no key starts with `#`), the same string on both clients. The default stores nothing.
- **Accents are derived from the base color.** `shared/accents.ts` holds each base color and `deriveAccent`, which keeps the hue and as much chroma as sRGB allows and moves the OKLCH lightness until the accent meets 5.2:1 on the light canvas (darker) or on the lightest dark glass (brighter). Light on-accent text is white; dark on-accent is a near-black of the same hue. The canvas's first glow is the base color too. In dark mode a pale base would lift the canvas through its glow, and the dense glass over a bright accent fill, until muted and label text fail, so the dark glow and the dark accent's starting lightness are dimmed until the glow tints the canvas to at most a fixed luminance. Of the presets this only dims Amber, slightly. With that, every color passes: the contrast test runs a 216-color grid over the sRGB cube besides the presets, and a 4,096-color grid passed when the rule was set. `deriveAccent` is itself the runtime contrast check: it searches for the lightness that meets the target, so a custom color needs no separate validation and is never refused.
- **Where accents are derived.** `bun run generate` writes the presets into `accents.css` (`<html data-accent>` rules setting `--accent`, `--on-accent`, `--accent-glow`), so their first frame needs no script. A custom color derives in the browser into a `<style id="custom-accent">` with `data-accent='custom'` rules, and the same rules are cached in `procrastimate-accent-css` so the pre-paint script paints them in the first frame. iOS derives every accent, preset or custom, at runtime with `Accents.deriveAccent` in `Core`, a port of the TS one; the generator only writes each preset's name and base. The `accents` test vectors (presets, a 64-color grid, and pale and dark edge cases) prove both clients derive the same values.
  `app-web/src/index.css` defines every color once per theme as a named role: `ink`, `muted`, `faint`, `accent`, `on-accent`, `surface`, `scrim`, the canvas, the glass materials and their solid fallback, the control fill, priority colors, date tones, and the twelve label colors. Components use only these tokens, never raw colors, so they never branch on the theme. Hairlines and quiet fills are `ink` at low opacity, so they flip with the theme for free. The roles mirror iOS semantic colors (label, secondary label, tint, materials) for the Liquid Glass port.
- **Dark glass stays glass.** Dark floating layers are translucent, blurred charcoal with a faint light edge, not opaque gray, so layering reads the same in both themes.
- **WCAG AA for all text.** Every text token meets 4.5:1 against every surface it sits on, in both themes, including the warm and cool canvas glows, chips, and the tinted highlights behind parsed quick add phrases. Dense glass is checked over what can scroll or slide beneath it: the canvas, task list text averaged by the blur (ink at 25%), and the accent fill. The solid fallback material is checked too. A unit test reads the tokens from `index.css` and enforces this, so a color tweak that breaks contrast fails CI. Priority colors are for graphics only (flags and checkboxes, held to 3:1), so priority labels are `ink` next to a colored flag, and destructive text uses the red date tone. The same test fails when a color has a light value but no dark one, so a new token, such as a parser highlight, cannot ship in one theme only. Meeting it darkened the light accent and date tones slightly. Dark mode uses a brighter accent with dark text on accent fills, because no single accent passes against both white text and a dark canvas. The test runs for every theme color in both themes.
- **No flash of the wrong theme.** An inline script in `app.html` sets `<html data-theme>` and the `theme-color` meta for the browser chrome from the saved choice before first paint, and an inline style sets the matching `color-scheme`. The Svelte app then owns the theme and keeps it in sync.
- **Switching crossfades.** A theme change runs a short view transition (about 220 ms) over the whole page, and skips it under reduced motion.
- **Where it lives.** A segmented control, and two rows of five swatches, the last one `Custom`, in Settings. See Settings.
- **iOS follows the choice live.** `.accent`, `.onAccent`, and `.accentGlow` read the shared `ThemeSettings`, which derives the chosen color once per change, so every view that draws them re-renders on a change, and the window's `tintColor` carries it into sheets and system chrome that would otherwise use the `AccentColor` asset.
