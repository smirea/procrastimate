# Recurring tasks

- **Completing moves the task.** Checking off a recurring task moves its due date to the next occurrence instead of closing it. It stays in its list with the new date, and an undo toast reads `Completed "<title>", next due <date>`. Undo restores the previous date and reminders.
- **Next occurrence.** The next date is the first one after today, stepping whole intervals from the current due date. A weekday set steps to the next listed day of the same week, and after the last listed day to the first listed day of the week `interval` weeks later. Weeks start on Monday. A due date moved off the set steps to the next listed day after it. Completing early moves one interval. Completing an overdue task skips the missed occurrences instead of leaving it overdue. A recurring task with no due date counts from today. This matches Todoist's `every`. Todoist's `every!`, which counts from the completion date, is not supported.
- **A monthly repeat on a day keeps its day.** A repeat typed with a day, such as `every 31st` or `every month on the 20th`, stores that day (`day`, 1 to 31) on the monthly recurrence. Each occurrence lands on that day, or on the last day of a month that lacks it, as Todoist does: the 31st goes Jan 31, Feb 28, Mar 31, Apr 30. The day is part of the repeat, not the due date, so moving the due date to the 20th of a repeat on the 3rd still completes to the next 3rd, and the chip reads `Every month on the 3rd`, so the rule stays visible. It lives in the JSON `recurrence` column, so it needed no schema migration. The repeat menu's presets replace it, and a custom monthly interval keeps it.
- **A monthly repeat on a weekday keeps its weekday.** A repeat typed with the nth weekday, such as `every 3rd Monday`, `every last Friday`, or `every month on the first Monday`, stores it (`nth`: `week` 1 to 4, or -1 for the last, and `weekday`) on the monthly recurrence. Each occurrence lands on that weekday of the month, so the last Friday goes Oct 30, Nov 27, Dec 25. There is no 5th, because most months lack one, and `last` covers what people usually mean by it. Like `day`, it is part of the repeat, so a moved due date still completes to the next 3rd Monday, and the chip reads `Every month on the 3rd Mon` or `Every month on the last Fri`. It lives in the JSON `recurrence` column next to `day`, so it needed no schema migration, and a repeat sets one of the two. The repeat menu offers it after `Every month`, as the due date's weekday of the month, counting the 29th to the 31st as the last. The other presets replace it, and a custom monthly interval keeps it.
- **A repeat never leaves the valid date range.** An interval is 1 to 999, which the schema enforces, so the server rejects a larger one. `stepRecurrence` and `alignToRecurrence` in `shared/task.ts`, ported to `Dates`, are the one boundary every computed repeat date passes through: they return null for an interval out of range or for an occurrence after 9999-12-31. Such a date is not a `DateKey`, so the server would reject the write, and on iOS a huge interval overflowed the month math and trapped. Completing a repeat with no occurrence left closes it like a task that does not repeat. Quick add keeps a repeat with too long an interval as text (see [Quick add](quick-add.md)).
- **Months clamp.** A monthly repeat without a day, such as `every month` or the `Every month` preset, on the 29th to 31st lands on the last day of a shorter month, and every later occurrence counts from that clamped date, so a repeat on the 31st becomes a repeat on the 28th after February. That holds whether the task is completed on time or overdue: Jan 31 completed on Mar 1 skips Feb 28 and lands on Mar 28, the same date on-time completions reach. A yearly repeat on Feb 29 becomes Feb 28 the same way. Type the day, as in `every 31st`, to keep it.
- **Reminders follow.** Relative reminders follow the new due time on their own. Absolute reminders shift by the same number of days as the due date, which for a weekday set varies with the gap to the next listed day. Each one fires once when its new time comes, like any reminder. The new due time notifies on its own too, because a due time is a reminder.
- **Editing.** The repeat chip in task details sets a preset (every day, weekday, week on the due weekday, month, or year), a custom interval, a weekday set, or `Don't repeat`. A row of seven weekday toggles, Monday first, at the top of the menu, edits the set and keeps the menu open. A plain weekly repeat starts the set from its due weekday. Any other repeat, or none, starts an empty set, so the first toggle makes a weekly repeat on that day. The last selected day cannot be turned off, so clearing goes through `Don't repeat`. A set of one day is stored as a plain weekly repeat on that day, the same shape `every fri` parses to, so the `Every Fri` preset shows as selected. A custom weekly interval keeps the set. The due date moves to the first listed day on or after the due date the menu opened with, so toggle order never changes the result. Setting a repeat on a task without a date dates it today, and removing the date removes the repeat, because a repeat needs a date to count from. Typing a repeat into the title replaces the current one.
- **Completed list.** A recurring task shows in completed lists once, at its latest roll (`lastCompletedAt`), with the repeat icon and a checkbox that only shows the completion, since the task is still open and there is nothing to reopen. Earlier rolls do not show, because a recurring task keeps no history of past occurrences and the activity log is online only, which a local-first list cannot wait on; task details' Activity lists every completion when online. A reopened task keeps `lastCompletedAt`, so a task counts as rolled only while it still repeats.
- **Display.** Rows show a repeat icon next to the due date. Inbox lists only the next occurrence, under its day. A weekday set reads `Every Mon, Wed, Fri`, Monday first, or `Every 2 weeks on Tue, Thu`. The stored set is sorted Monday first with each day once, and the schema refuses any other order, as stepping to the next occurrence assumes it. A date key and a time of day are refused unless they name a real day and clock time; `2026-02-31` has the shape and no day.
