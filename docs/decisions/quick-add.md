# Quick add and natural language

- **Todoist quick add is the reference.** One input captures the title and its attributes. Recognized phrases are highlighted inline as you type and removed from the saved title. A typed phrase always parses. To undo one, Stefan edits the text or clears the attribute from its chip's menu: `No date` for the date, `Priority 4` for priority, and `Inbox` for the project.
- **The same parser runs in quick add and in the task details title field.**
- **Saving closes quick add and shows the task.** After a save, quick add closes, the list the task landed in opens (the open label or project when it holds the task, else the task's project, else Inbox or No date), and the list scrolls to the row and flashes it. Quick add no longer stays open for the next task, because seeing where a task went beats batch entry for one user capturing on the go.
- **Quick add stays a capture surface, not a second details editor.** It holds what Stefan types in one motion: the title line, its chips, and subtasks. Notes, location and event edits beyond their chips, and reordering stay in task details, which is the full editor. A full form would slow the common case, a one-line task saved with Enter, to serve the rare one that task details already covers right after saving.
- **Subtasks in quick add.** The checklist chip, or `Subtasks` in the `+` menu, opens a subtask field under the title. Return adds the line to a list under the title and keeps focus for the next. Each line parses like task details' `Add subtask`: dates, repeats, priority, reminders, and `@` labels, with no `#` project. Each line shows its parsed date, repeat, and labels, and an `×` removes it before saving. Saving creates the parent, then each subtask in order under it, including a line still in the field, and then closes quick add and reveals the parent like any save, its row showing `0/n`. Return in the title field still saves, and Return on an empty subtask field saves too, so a list ends with a double Return. The chip shows the count once lines exist. An empty field with no lines closes when it loses focus, and on the web Backspace in it returns to the title. Escape or `Cancel` discards the title and every subtask.
- **Repeated phrases.** Date, recurrence, priority, and project take the last matching phrase, because attributes usually trail the title. `Today task today` saves `Today task` due today. Reminders and labels keep every match.
- **The configuration row is the only timing readout.** Below the input, the date chip shows the parsed date and time, and chips show the repeat and each reminder, so Stefan can read what will be saved. In task details the chips show the title's parsed values while he edits, before Enter or blur saves them. A due time still notifies on its own, as the Reminder entry in [Domain](domain.md) describes. A glass timing preview above the input, such as `Tomorrow at 5:00 PM · Notifies at 5:00 PM · Repeats every Mon`, was removed from quick add and the task details title because it repeated that row. The add-subtask field dropped it too, so its highlighted phrases are the readout until the subtask is added.
- **One scrolling chip row with a `+` menu, as in Todoist.** The attribute chips sit on one line that scrolls sideways and never wraps, and the end that has more chips past it fades. A `+` pinned after the row opens a menu of every attribute action, including the ones not shown in the row. Picking one shows its chip for this draft, scrolls to it, and opens its picker. `Subtasks` opens the subtask field instead, and on iOS `Priority` is a submenu with the four levels. A wrapping row grew taller with every chip and pushed the input around above the keyboard, and the `+` keeps rare attributes one tap away without spending row space on them.
- **Pinned buttons are a synced setting.** Stefan picks which buttons the row shows, from the `+` menu (a pin beside each action on the web, a `Customize row` submenu of toggles on iOS) or from `Quick add buttons` in Settings. The choice is `quickAddButtons` on the synced settings record, so web and iOS show the same row. It defaults to Todoist's row: Date, Priority, and Reminders, plus the subtask checklist quick add already had. `shared/quick-add-buttons.ts`, ported to `QuickAddButtons`, owns the order and the toggle rule.
- **A set attribute always shows.** An attribute that holds a value, whether typed, picked, or from a list default, shows its chip even when it is not pinned, so the row stays the readout of what will be saved.
- **Chip order.** Date, Priority, Reminders (with each typed reminder spelled out after it), Repeat, Labels, Subtasks, then on iOS Location and Event, then the `Create #name` or `Create @name` chips. The order is fixed, so a chip never moves when another appears. The web has no Location or Event, since only iOS sets them. A picked event hides Date and Repeat, as in task details. Labels is one chip with every label, typed or picked; unchecking a typed label in its picker removes the `@name`. A repeat picked with the Repeat chip replaces a typed one, and moves the date when the repeat starts on another day. A set priority fills the flag with its level's color (P1 red, P2 orange, P3 blue) on a capsule tinted with that color, and Priority 4 is a plain gray outline flag. Task details keeps its labeled `Priority` chip.
- **Pickers win over text.** Choosing a date, priority, or project with a picker removes the matching phrase from the input. Pickers close on selection, except the due picker's calendar, which stays open so a time can follow.
- **One due picker.** The date chip in quick add and task details opens one popover with four preset tiles (`Today`, `Tomorrow`, `Next week`, and `No date`), a month calendar, and a time row. Every pick commits at once. Tiles, not rows, keep it short enough to sit above the iPhone keyboard. The web draws its own Monday-first calendar, because the native date and time inputs were clumsy on desktop. iOS uses the native graphical `DatePicker`.
  - **Add time never commits a default.** `Add time` swaps the calendar for a time view: on the web a field that reads typed times such as `5:30pm` (the quick add time grammar) above a list of half hours, opened at the set time or the next half hour, and on iOS a wheel with a `Set <time>` button. Only a time Stefan picks, types, or scrolls to is saved. The old `Add time` saved 9am at once.
  - **A picked time never lands in the past.** It keeps a date still ahead. With no date, today's date, or an overdue date, it lands on the next time that clock time comes around, today or tomorrow once it has passed, the same rule as a typed time with no day. A calendar day picked after the time is a chosen day and wins. `dueAtTime` in `shared/task.ts`, ported to `Dates.dueAtTime`, owns the rule, and quick add's parser calls it for a time with no typed day.
  - **Removing the time** is the `x` beside the time row, which keeps the date.
- **Days.** `today`, `tomorrow`, and `tom`, `tmr`, `tmrw`. `tonight` is today at 8pm. `eod` is today at 5pm. `eow` is the coming Friday at 5pm, today on a Friday. A typed time replaces these default times, as in `tonight 9pm`.
- **Weekdays.** `mon` to `sun` and the full names mean the next one, counting today, so `wed` on a Wednesday is today. `next fri` and `nxt fri` mean the Friday of next week, which starts on Monday. `next week` is next Monday.
- **Offsets.** `2d`, `1w`, `2wk`, `3mo`, and `in 3 days`, `in 2 weeks`, `in 3 months`, `in 1 year` set a date with no time. `5m`, `5min`, `5 mins`, `2h`, `2hr`, `2hrs`, `2 hrs`, `in 2 hours`, and a bare `in 30` set the date and time that many minutes or hours from now. `mo` always means months and `m` always means minutes. Spelled-out units such as `2 hours` or `3 days` need `in`, because a bare length such as `study 2 hours` is not a due date. Months clamp to the end of a shorter month, so Jan 31 plus `1mo` is Feb 28.
- **Dates.** `oct 15`, `15 oct`, `15th october`, `the 15th`, and `10/15` or `10/15/2027`. A month name may be short or full, in any case, with a period after a short one (`Dec. 25`, `Sept. 30`), and the day may take an ordinal either way round, including `October the 20th`, `20th of October`, and `the 1st of December`. A weekday before it, as in `Monday, October 19` or `tue oct 20`, is part of the phrase and the date wins. A month and day can take a year, as in `jun 21 2027` or `may 23, 2027`, which is how Todoist writes dates beyond this year. A `20th of` needs its ordinal, so `chapter 3 of may` stays text. A date without a year is the next one, counting today. `the 15th` is the next 15th. Slash dates are month first, unless the first number cannot be a month, so `15/10` is October 15. When neither number can be a month, as in `15/14`, it stays text.
- **Times.** `5pm`, `5 pm`, `5p`, `11a`, `5:30p`, `17:30`, `1730`, `noon`, and `midnight`, optionally after `at`. A time can sit before or after a day, as in `fri 5p` or `9am fri`, and a comma may separate them, as in `Oct 19, 10am` or `October 20th, 2027, 3pm`, because dictation writes dates that way. Without that, the day and the time were two phrases and the time alone won, so the date was lost.
- **Punctuation after a removed phrase stays on the title.** `Pay rent October 20th.` saves `Pay rent.`, and `Call mom tomorrow, then dad` saves `Call mom, then dad`. A comma or colon left at the very start, as in `Tomorrow, call mom`, is dropped.
- **A time with no day.** It lands on the next time that clock time comes around. That is today, or tomorrow once the time has passed, so `9am` typed at 10am is tomorrow at 9am and `midnight` is the coming midnight. A time equal to the current minute stays today. A typed day always wins, even if that leaves the time in the past, as with `wed 9am` typed on Wednesday at 10am. A time with no day uses the date set outside the text when there is one, such as the task's existing date in task details or the Today default in quick add, unless that would put it in the past. Then it takes the next time that clock time comes around, so `9am` typed at 10am from Today is tomorrow at 9am, and `9am` on an overdue task is the next 9am. A repeat with no typed date follows the same rule. This matches Todoist as far as we remember it. We have not checked it against live Todoist.
- **Recurrence.** `every day`, `daily`, `weekly`, `monthly`, `yearly`, `every week`, `every mon`, `every 2d`, `every 2 weeks`, `every 3mo`, `every other week`, `every weekday`, `every workday`, or `weekdays`, and a yearly repeat on a date, `every march 2nd` or `every 2nd march`, which starts on the next one, counting today. A date that does not exist, such as `every feb 30`, stays text. A task stores it as an interval and a unit (day, weekday, week, month, or year), plus a weekday set for a weekly repeat on several days. A repeat on a named day such as `every mon` is weekly and starts on that day. A weekday repeat typed on a weekend starts on Monday. Any other repeat with no typed date starts on the date set outside the text, such as a picked date, or else today. If its typed time has already passed today, it starts one interval later. A typed date such as `every fri oct 30` sets the first occurrence. Quick add and the task title store the repeat. See Recurring tasks for what completing one does.
- **Several weekdays.** A list of two or more weekdays joined by spaces, commas, slashes, `and`, or `&` is one repeat on that set, as in `every mon, wed`, `every mon and fri`, `gym mon wed fri 7am`, or `tue/thu`. It starts on the first listed day, counting today, and moves to the next listed day when its typed time has passed today. A typed date moves to the first listed day on or after it. A list that names one day, such as `every mon, monday`, is a plain `every mon`.
- **When a bare weekday list repeats.** Without `every`, a list repeats only next to a time, as in `mon wed fri 7am` or `7am mon wed fri`, or when it is slashed, as in `tue/thu`. A slash is compact schedule notation, so it needs nothing else. Anywhere else, as in `Discuss mon wed plan` or `Swap tue and thu shifts`, the whole list stays text and sets no date, because it names no single day and is most likely prose. A single weekday next to a time is still a due date, so `Lunch fri 12pm` does not repeat.
- **Priority.** `p1` to `p4`. `!!!` and `urgent` mean `p1`. `!!` and `important` mean `p2`. A single `!` is never parsed, because it is common in titles.
- **Reminders.** `remind me 30m before`, `remind 5m before`, `remind me 1 hour before`, `r5m`, `r1h`, `r2d`, `r1w`, `remind me at 4pm`, and `remind me tomorrow 9am`. A reminder at a time with no date lands on the due date. With no due date it lands today, or tomorrow once that time has passed. Todoist uses a leading `!` for reminders. ProcrastiMate does not, because `!!` is a priority shortcut.
- **Words stay words.** Phrases only match whole words, so `mon` in `lemon` or `5m` in `2.5m` never parse. Before matching, the parser masks text that only looks like a phrase:
  - `Tom` or `TOM` is a name. Only lowercase `tom` means tomorrow, and not after a word that takes a person, such as `call`, `email`, `with`, `to`, or `for`.
  - `tom`, `sun`, `sat`, `wed`, `daily`, `weekly`, `monthly`, and `yearly` stay text when an ordinary word follows them, as in `sun hat`, `sat on`, or `Daily standup`. At the end of the text, or before a time, `at`, another phrase, or `and` plus a weekday, they parse. So `I sat and waited` stays text while `every sat and sun` repeats.
  - A bare weekday list with no `every`, no time next to it, and no slash stays text, as in `Plan mon wed fri rota`.
  - A number after an address word (`apt`, `unit`, `suite`, `room`, `floor`, and similar) or before a street word (`st`, `ave`, `rd`, `blvd`, and similar) is part of an address, so `Apt 5p` and `5p Baker St` stay text.
  - A bare `19xx` or `20xx` is a year. Write `at 2030` for 8:30pm.
  - A number after `$`, `€`, or `£`, or after a decimal point, is not a time or an offset.
  - `1/2` always reads as January 2.
  - A date or reminder that lands after 9999-12-31, as in `3929284d` or `in 8000 years`, stays text. Such a date is not a valid date key, and the server would reject the op and, with it, the rest of the device's outbox.
  - A word right after `#` or `@` is a name or a handle, so `@5pm`, `@tomorrow`, `@p1`, and `@urgent` stay text.
  - A link is never a phrase, so `5m`, `p1`, `3pm`, `#anchor`, or `@user` inside a URL or a Markdown link stays part of it. The parser masks every link `linkify` finds (see Links in [Domain](domain.md)) before any rule runs.
- **Parsing order.** Reminders claim their text first, then recurrence, project, section, labels, priority, and the due date. A later rule never reads text an earlier rule recognized, so `every wed 9am` is one repeat and one time. That includes an earlier copy of a repeated phrase.
- **Projects.** `#Name` assigns an existing project, matched case-insensitively. It is highlighted only when the project exists.
- **Sections.** `/Name` puts the task in a section of the project typed with `#`, else of the project quick add opened with, matched case-insensitively, as in Todoist. With no project in effect it stays text. `/` opens that project's sections with a create row, like `#`. See [Sections](sections.md).
- **Labels.** `@name` adds an existing label, matched case-insensitively, anywhere in the text. Every `@label` counts, and a label typed twice is added once. Like `#`, the `@` must start the text or follow a space, and the name must end the word, so `bob@site.com`, `you@calls`, `@calls.com`, and `@callsign` stay text. An `@word` that names no label stays in the title. Typing labels in the task details title adds them to the task's labels and never removes any.
- **`#` autocomplete.** Typing `#` at the start of the text or after a space opens a project list above the input, filtered by the text after `#`. The filter may contain spaces only while it still starts a project name, so multi-word names stay searchable. Picking replaces the fragment with `#Name ` and keeps focus in the input.
  - **Order.** Best match first: exact name, then name prefix, then word prefix, then substring, all case-insensitive. Within a tier, the project that most recently received a new task comes first, then alphabetical. Recency is derived from task creation times, so it needs no stored field.
  - **Create.** When no project name equals the filter, the last row offers `Create project "<filter>"`, which creates the project and inserts it.
  - **Keys.** Up and down move the selection, Tab picks, and Enter picks unless the filter already names a project exactly and the selection was not moved, so `Fix sink #home` plus Enter still saves. Escape closes the list for that `#` without closing the sheet. Tapping a row picks it.
- **Unknown names offer to create, never silently.** Todoist creates labels on the fly and offers to create projects. ProcrastiMate does neither on its own, because a stray `#` or `@` word should never add a project or label Stefan did not mean. Every `#name` or `@name` that names nothing yet shows a `Create #name` or `Create @name` chip in the configuration row, and only a tap on the chip, or Enter or Tab on the suggestion list's create row while the caret is in the name, creates it. Saving with the name still unknown keeps it as title text. The chip hides for the name the suggestion list is open on, since the list already offers it. A name is a sigil at the start of the text or after a space, then letters, digits, `_`, or `-`, ending at a space or the end after any sentence punctuation, so `@calls,` offers `calls` and `@site.com` offers nothing. Text the parser claimed is skipped, so `#Side Project` never offers `#Side`, and each name is offered once. The rule is `unknownNames` in `shared/name-search.ts`, ported to `NameSearch.unknownNames`. Quick add only: the task details title keeps an unknown name as text, and its labels picker creates labels.
- **`@` autocomplete.** `@` opens a label list with the same rules as `#`: the same fragment rules, order, create row (`Create label "<filter>"`), keys, and taps. Recency is the newest task carrying the label. When the caret follows both a `#` and an `@`, the nearer one wins. One suggestion list serves both, driven by a table of the two kinds, so a fix to one applies to the other.
- **Not yet compared against live Todoist.** Todoist's login captcha blocked automated access, so the repeated-phrase rule and the `!!` mapping are our own calls.
