# Testing

- **What the suite is for.** Tests cover parsing (quick add and the Ramble grammar), the shared functions recorded as TS-to-Swift vectors, the generated API and Swift types, a few real regressions, and a short end-to-end smoke. A test that only checks wiring, a mock, a framework, or a library, or that repeats a case already in a parser table or a vector, does not stay.
- **Parsers.** Quick add cases live in `shared/quick-add.test.ts` as tables. Ramble's grammar is the corpus in `shared/fixtures/ramble-corpus.ts`, run from `shared/ramble.test.ts`. The one ICU-versus-JavaScript difference that vectors cannot record is `QuickAddTests` in `app-ios`.
- **Vectors and generated types.** `bun run vectors` records every call to a `recorded` function into `shared/vectors/*.json`. The iOS `VectorTests` replay them. `APITests` checks the generated Swift types, including an outbox still carrying the 0/1 boolean bug. Generated files are git-ignored and rebuilt before every run, so none can be stale.
- **Regressions.** `server/src/account/sync.test.ts` accepts the 0 and 1 that older iOS builds sent as booleans. `scripts/test-guard.ts` refuses to start `bun test` when `TURSO_DATABASE_URL` points at production, and `scripts/test-guard.test.ts` locks that rule.
- **Unit tests.** `bun test`, colocated as `*.test.ts`. The natural-language parser and the Todoist import are tested with a fixed clock. Theme contrast is tested against the real tokens in `index.css`.
- **End to end.** Playwright runs every `app-web/e2e/*.e2e.ts` spec in the `desktop` project (Chromium, 1280×800). In dev mode it starts the Bun API on port 6131 next to Vite on 6130, so the sync tests reach a real in-memory account. Each test signs up as its own user. `EPHEMERAL=1`, which the Playwright servers and the unit tests set and production never does, keeps those runs off Turso so they cannot write the dev database, and uses a fixed auth secret with an in-memory user table. Hooks never run these tests. The full smoke stays in CI.
- **End-to-end determinism.** A spec waits for its condition, never a sleep or a retry. The `context` fixture fails a test on any uncaught error in its pages, so a crash in a handler cannot hide behind a passing assertion. The pinned clock catches an error thrown in a timer and logs it with `console.error(error)`, so `watchPageErrors` also counts a console error whose first argument is an Error; the app never logs one itself. `e2e/page-errors.e2e.ts` proves both paths. The `app` fixture waits for `document.fonts.ready`, since Linux CI's fallback font wraps text wider until Google Sans Flex arrives. A title that must be unique comes from `unique()` in `e2e/fixtures.ts`, whose suffix starts with a letter so quick add cannot parse it as a token. A spec clicks only what is fully in view when the scroll position matters, since Playwright scrolls a clipped target into view first. `App.row()` skips a row that is animating out, which `leaving` marks `aria-hidden`, so a row that moves between day sections resolves to one element mid-animation and a spec asserts on it directly. `App.settle()` waits for running animations. A field the web cannot set, such as an iOS place, is seeded with `App.pushFromOtherDevice`, which writes it through `/api/sync` as a second device of the same account. Writing the `procrastimate` localStorage document does not stick, since the page's next sync replaces it. A phone flow runs in the same project under `test.use({ viewport: { width: 393, height: 852 }, hasTouch: true, isMobile: true })`; below 768 px `App.openQuickAdd()` uses the floating `Quick add` button, and `App.openNavigation()` opens the drawer. `App.addCreating()` creates each unknown `#project` and `@label` from its chip before saving, and `App.closeDetails()` uses `Close`, since Escape in a details field leaves the sheet open. A spec that finds a real app bug keeps its assertion in a `test.fixme` named for the behavior, and the feature map says the step is skipped until the fix lands.
- **Hooks.** Lefthook's pre-commit and pre-push run `scripts/test-changed.ts` on the changed files: the colocated `*.test.ts` and any unit test that imports the changed module. `swift test` runs only when `app-ios` changed, and is skipped when `swift` is not installed. Web end-to-end stays in CI. The hooks start the script with `bun --no-env-file`: `bun test` never loads `.env.local`, but a plain `bun` script does and its child `bun test` inherits it, which pointed Better Auth at the dev Turso database and its shared sign-up rate limit.
- **iOS.** `swift test` in `app-ios/` runs the `Core` unit tests, including `VectorTests`, on macOS and on the Linux `core-linux` job. There is no XCUITest target. Agents verify iOS UI with throwaway XCUITests through `./sim test` ([Workflow](workflow.md)), which never enter the repo. The macOS `core` and `app` jobs run on pull requests that can change the app and on a manual dispatch. `app` checks the Debug and Release API URLs and the privacy manifest. See [iOS app](ios.md).
- **Linux Swift builds with the native build system.** `core-linux` runs `swift test --build-system native` in the pinned `swift:6.4.1` image. SwiftPM 6.4 made Swift Build the default backend, and on Linux its planner segfaults (exit 139) in about one run in 60: three of roughly 190 `core-linux` jobs from October 14 to 16, 2026. Every crash had the same crashing thread, libdispatch's manager thread in `_dispatch_event_loop_drain`, inside `swift-package` at `Planning` or `Pre-planning`, before any of our code compiled. The `SpecRegistry`, `LazyCache`, and `completeTaskWithClosure` frames are on other planner threads that were mid-work. This is [swiftlang/swift-build#1786](https://github.com/swiftlang/swift-build/issues/1786), a libdispatch use-after-free that Swift Build reaches by reading subprocess output with `DispatchIO`. It also hits 6.4.0 and the Ubuntu 24.04 image, so changing the patch or the base image does not avoid it. Our code is not involved: the crash comes before it compiles, and five Thread Sanitizer runs of the `Core` tests report nothing. 300 clean builds in arm64 Docker did not reproduce the crash. The native backend uses the same compiler and runs the same tests, and `swift:6.2` used it with no crash. The tag is pinned so the image cannot change under the job unnoticed. When a release fixes #1786, bump the tag and drop the flag. SwiftPM has deprecated `native`; when a release removes it, the job fails loudly. The job never retries, since a retry would also hide a real crash. Local `swift test` keeps the default backend, so a rare crash there needs a rerun.
- **Feature map.** `.cursor/skills/verify-procrastimate/features/` describes each user-facing feature and how to drive it by hand. Keep it in sync with every change. A step may cite the test that proves it, and `scripts/feature-map-citations.test.ts`, part of `bun test`, fails when a cited spec file, test title, Swift test, Playwright project, or saved screenshot does not exist. Its message lists each stale line; point it at the real test, write the test, or drop the citation and keep the step manual. Agents trust these citations, so a stale one sends them to a test that proves nothing.
