# Testing

- **The bar.** A committed test states a rule someone decided (a business rule, an invariant, or a contract between two parts such as a wire format, sync, permissions, dates and recurrence, or parsing), breaking it would be silent or expensive, it checks outcomes through the module's public interface, and it runs in-process in milliseconds with no browser, simulator, network, real clock, or sleep. Its name is that rule in one sentence. Tests of wiring, config, copy, layout, list order nobody decided, UI timing, or anything the type checker guarantees do not stay. The full rules are the `tests` skill (`~/code/ai-files/skills/tests/SKILL.md`).
- **No browser, end-to-end, or UI tests.** The Playwright suite was deleted in November 2026: half of local test failures were upkeep of the tests themselves and most failed CI runs were flakes. UI and wiring are verified by running the real app, with the feature map's steps, and logic behind a screen, such as which options a menu offers, a grace period, or a backoff, lives in a plain module with a unit test that the component calls.
- **Parsers.** Quick add cases live in `shared/quick-add.test.ts` as tables. Ramble's grammar is the corpus in `shared/fixtures/ramble-corpus.ts`, run from `shared/ramble.test.ts`. The one ICU-versus-JavaScript difference that vectors cannot record is `QuickAddTests` in `app-ios`.
- **Vectors and generated types.** `bun run vectors` records every call to a `recorded` function into `shared/vectors/*.json`. The iOS `VectorTests` replay them. `APITests` checks the generated Swift types: a one-character highlight decodes, and an optional field refuses `null` as zod does. Generated files are git-ignored and rebuilt before every run, so none can be stale.
- **Server tests run on in-memory SQLite.** `server/src/test-app.ts` opens a fresh `bun:sqlite` database per `testApp()`, migrated as the Bun server and the `App` object migrate, and serves the same `handle` the object does, so a test signs up through Better Auth and calls routes the way clients do; a file shares one across its tests. The database refuses a statement past the Durable Object's 100 bound parameters, as production would. A test that shares its file's database seeds what it reads, its own person, task, share, or subscription, so it passes run alone with `-t` as well as after the tests above it. Sync tests post the engine's protocol with `syncAs` from a `device()`, and `upload` keeps the old name for one device's one request. Ramble's socket tests drive a fake upstream and a fake clock, and wait for the message they expect, such as `started` or `ended`, never a sleep. A session sends `ended` only after its seconds are stored, so a test reads the usage table right after it.
- **Unit tests.** `bun test`, colocated as `*.test.ts` beside the module it covers. A timer-driven rule runs on `jest.useFakeTimers()`, which also moves `performance.now()`. The natural-language parser and the Todoist import are tested with a fixed clock. `scripts/test-timezone.ts`, preloaded first, runs every test in `America/New_York`, the zone `bun run vectors` records in, since a shell in UTC never crosses a daylight-saving change and the DST cases then prove nothing. Theme contrast is tested against the real tokens in `index.css`.
- **No performance harness.** The Playwright audit (`app-web/perf/audit.perf.ts`) went with the suite. [Performance audit](../perf-audit.md) keeps the numbers it measured and what they led to; measure a new question in the running app, with Chromium's performance panel at 4x CPU throttling.
- **Hooks.** Lefthook's pre-commit and pre-push run `scripts/test-changed.ts` on the changed files: the colocated `*.test.ts` and any unit test that imports the changed module. When the iOS app's inputs changed, it regenerates the Swift sources and runs `swift test`, and skips it when `swift` is not installed. `bun run test:swift` does the same from a shell: `swift test` reads the git-ignored `app-ios/Sources/Core/Generated` files, which fail the build when stale. The hooks start the script with `bun --no-env-file`: `bun test` never loads `.env.local`, but a plain `bun` script does and its child `bun test` inherits it, which pointed Better Auth at the dev database (Turso at the time) and its shared sign-up rate limit. No hook starts a browser, a simulator, or a server.
- **iOS.** `swift test` in `app-ios/` runs the `Core` unit tests, including `VectorTests`, on macOS and on the Linux `core-linux` job. There is no XCUITest target. Agents verify iOS UI with throwaway XCUITests through `./sim test` ([Workflow](workflow.md)), which never enter the repo. The macOS `core` and `app` jobs run on pull requests that can change the app and on a manual dispatch. `app` checks the Debug and Release API URLs and the privacy manifest. See [iOS app](ios.md).
- **Linux Swift builds with the native build system.** `core-linux` runs `swift test --build-system native` in the pinned `swift:6.4.1` image. SwiftPM 6.4 made Swift Build the default backend, and on Linux its planner segfaults (exit 139) in about one run in 60: three of roughly 190 `core-linux` jobs from October 14 to 16, 2026. Every crash had the same crashing thread, libdispatch's manager thread in `_dispatch_event_loop_drain`, inside `swift-package` at `Planning` or `Pre-planning`, before any of our code compiled. The `SpecRegistry`, `LazyCache`, and `completeTaskWithClosure` frames are on other planner threads that were mid-work. This is [swiftlang/swift-build#1786](https://github.com/swiftlang/swift-build/issues/1786), a libdispatch use-after-free that Swift Build reaches by reading subprocess output with `DispatchIO`. It also hits 6.4.0 and the Ubuntu 24.04 image, so changing the patch or the base image does not avoid it. Our code is not involved: the crash comes before it compiles, and five Thread Sanitizer runs of the `Core` tests report nothing. 300 clean builds in arm64 Docker did not reproduce the crash. The native backend uses the same compiler and runs the same tests, and `swift:6.2` used it with no crash. The tag is pinned so the image cannot change under the job unnoticed. On October 26, 2026, a CI probe of clean `swift build --build-tests` runs on the default backend crashed 13 times in 1,700 on `swift:6.4.1`, every time on a `DispatchWorker` thread in `_dispatch_event_loop_drain`, and 0 times in 1,150 on the `nightly-main-noble` 6.5-dev snapshot. Swift Build's `main` reads subprocess output through swift-subprocess, which polls with its own epoll instead of `DispatchIO`, while `release/6.4.x` still uses `DispatchIO`. So the fix should ship with 6.5, but no release has it, and a nightly compiler is too unstable and slow to pin. The weekly `Swift Build crash watch` workflow (`.github/workflows/swift-build-1786.yml`) watches for the fix. It fails when #1786 closes, or when a Swift release newer than the pinned tag finishes 500 clean default-backend builds without a crash. Run it by hand with `force` to stress the pinned release. When it fails, bump the tag, drop the flag, and delete the watch. SwiftPM has deprecated `native`; when a release removes it, the job fails loudly. The job never retries, since a retry would also hide a real crash. Local `swift test` keeps the default backend, so a rare crash there needs a rerun.
- **Feature map.** `.cursor/skills/verify-procrastimate/features/` describes each user-facing feature and how to drive it by hand. Keep it in sync with every change. A step may name the unit or Swift test that proves its logic; nothing checks those names, so rename a test and its citation together.
