# Testing

- **What the suite is for.** Tests cover parsing (quick add and the Ramble grammar), the shared functions recorded as TS-to-Swift vectors, the generated API and Swift types, a few real regressions, and a short end-to-end smoke. A test that only checks wiring, a mock, a framework, or a library, or that repeats a case already in a parser table or a vector, does not stay.
- **Parsers.** Quick add cases live in `shared/quick-add.test.ts` as tables. Ramble's grammar is the corpus in `shared/fixtures/ramble-corpus.ts`, run from `shared/ramble.test.ts`. The one ICU-versus-JavaScript difference that vectors cannot record is `QuickAddTests` in `app-ios`.
- **Vectors and generated types.** `bun run vectors` records every call to a `recorded` function into `shared/vectors/*.json`. The iOS `VectorTests` replay them. `APITests` checks the generated Swift types, including an outbox still carrying the 0/1 boolean bug. Generated files are git-ignored and rebuilt before every run, so none can be stale.
- **Regressions.** `server/src/account/sync.test.ts` accepts the 0 and 1 that older iOS builds sent as booleans. `scripts/test-guard.ts` refuses to start `bun test` when `TURSO_DATABASE_URL` points at production, and `scripts/test-guard.test.ts` locks that rule.
- **Unit tests.** `bun test`, colocated as `*.test.ts`. The natural-language parser and the Todoist import are tested with a fixed clock. Theme contrast is tested against the real tokens in `index.css`.
- **End to end.** Playwright runs every `app-web/e2e/*.e2e.ts` spec in the `desktop` project (Chromium, 1280×800). In dev mode it starts the Bun API on port 6131 next to Vite on 6130, so the sync tests reach a real in-memory account. Each test signs up as its own user. `EPHEMERAL=1`, which the Playwright servers and the unit tests set and production never does, keeps those runs off Turso so they cannot write the dev database, and uses a fixed auth secret with an in-memory user table. Hooks never run these tests. The full smoke stays in CI.
- **End-to-end determinism.** A spec waits for its condition, never a sleep or a retry. The `app` fixture waits for `document.fonts.ready`, since Linux CI's fallback font wraps text wider until Google Sans Flex arrives. A title that must be unique comes from `unique()` in `e2e/fixtures.ts`, whose suffix starts with a letter so quick add cannot parse it as a token. A spec clicks only what is fully in view when the scroll position matters, since Playwright scrolls a clipped target into view first. A row that moves between day sections exists twice while it animates, so a spec waits for the row at its destination before it counts rows. `App.settle()` waits for running animations. A field the web cannot set, such as an iOS place, is seeded with `App.pushFromOtherDevice`, which writes it through `/api/sync` as a second device of the same account. Writing the `procrastimate` localStorage document does not stick, since the page's next sync replaces it.
- **Hooks.** Lefthook's pre-commit and pre-push run `scripts/test-changed.ts` on the changed files: the colocated `*.test.ts` and any unit test that imports the changed module. `swift test` runs only when `app-ios` changed, and is skipped when `swift` is not installed. Web end-to-end stays in CI. The hooks start the script with `bun --no-env-file`: `bun test` never loads `.env.local`, but a plain `bun` script does and its child `bun test` inherits it, which pointed Better Auth at the dev Turso database and its shared sign-up rate limit.
- **iOS.** `swift test` in `app-ios/` runs the `Core` unit tests, including `VectorTests`, on macOS and on the Linux `core-linux` job. There is no XCUITest target. The macOS `core` and `app` jobs stay manual until a release. `app` checks the Debug and Release API URLs and the privacy manifest. See [iOS app](ios.md).
- **Feature map.** `.cursor/skills/verify-procrastimate/features/` describes each user-facing feature and how to drive it by hand. Keep it in sync with every change. A step may cite the test that proves it, and `scripts/feature-map-citations.test.ts`, part of `bun test`, fails when a cited spec file, test title, Swift test, Playwright project, or saved screenshot does not exist. Its message lists each stale line; point it at the real test, write the test, or drop the citation and keep the step manual. Agents trust these citations, so a stale one sends them to a test that proves nothing.
