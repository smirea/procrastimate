# Workflow

- **One PR per thread, never stacked.** Each thread ships one PR off `master`.
- **Fold small follow-ups in.** Before starting a new thread for new work, consider folding it into an existing open PR or thread when it touches the same area or files or is a small follow-up. Start a new thread only when the work is genuinely independent.
- **Rebase only on a real conflict.** Rebase a PR only when GitHub reports a conflict. PR CI already tests the merge with `master`, so do not rebase every open PR after each merge.
- **Decisions live one file per area.** Each area of `docs/decisions/` is its own file, so parallel PRs don't conflict. Record a decision in the matching area file, and add a new file when no area fits.
- **Workers build features themselves.** Never hand the whole build to a helper sub-agent that can't receive messages.
- **Run only the relevant tests locally.** Run the unit and e2e specs that cover the change. The full suite runs in CI.
- **iOS CI runs only where the app can change.** The macOS `core` (`swift test`) and `app` (API URL and build checks) jobs in `.github/workflows/ios.yml` run on a pull request whose diff touches `app-ios/`, `shared/`, the Swift generator, or the other inputs its `changes` job lists, and on a manual `workflow_dispatch`. They skip `master`, since TestFlight archives every such merge. The Linux `core-linux` job runs `swift test` on every pull request and push. A job skipped by `if` reports success, so a required check of that name does not block the merge.
- **Screenshots only for UI changes.** Attach 2 to 4.

## Clients

- **Every feature is built for all clients at once.** Web and iOS today. A feature request is planned and built for every client where it makes sense, not for one client with the others catching up later.
- **Each feature plan names its clients.** It lists the target clients and says why any are excluded. Some clients get a subset; a future Apple Watch app, for example, gets only what suits a watch.
- **Web and iOS slices are planned together.** Shared logic lands once in `shared/` with its Swift port through the test vectors. Each UI slice has a twin on the other client. Automated UI pairs are not part of the suite; parsers, vectors, and the auth and sync smoke are ([Testing](testing.md)). The twins may run as parallel PRs.

## Parallel agents

- **Every agent worktree is sandboxed by script.** `scripts/setup-worktree.ts [branch]` renames the worktree's branch to its final name and gives it its own ports (a git-ignored `.env.override` that env-manager applies to every target), its own Postgres databases and PowerSync containers in Docker for dev and for Playwright (see [Dev hosting](dev-hosting.md)), and a git-ignored `./sim` bound to its own simulator. `scripts/teardown-worktree.ts <worktree>` removes all of it, containers and databases included, from the main checkout once the PR is merged, and `scripts/worktree-gc.ts` reclaims what a vanished worktree left behind. The simulator is named after the branch, or after the worktree directory on a detached HEAD. A permission alert raised before the launcher granted permissions survives later grants and relaunches, so `./sim` reboots its own simulator once if it is booted without the marker file in its data directory. Every launch after that is already granted. Rules that a script can enforce live in the script, not in prompts.
- **Agent simulators run headless and are reclaimed by script.** `./sim` boots its simulator without opening Device Hub unless given `--show`. Every `./sim` command writes the worktree's path into the simulator's data directory, and that file's mtime is the simulator's last use. `scripts/worktree-gc.ts` shuts down a claimed simulator unused for 15 minutes that no running process names, deletes one whose worktree is gone, and deletes DerivedData of removed checkouts. The orchestrator runs it on every wake. A custom simctl device set would keep agent simulators out of Device Hub entirely, but `xcodebuild` can't see devices in one, so UI tests couldn't run there.
- **Throwaway iOS UI tests run through `./sim test`.** The repo keeps no XCUITest target ([Testing](testing.md)). `./sim test <file.swift>` builds and installs the app, generates a host app and UI test bundle under the worktree's git-ignored `app-ios/DerivedData/uitest`, runs the given files against the installed app under a time limit, and stops the simulator. AXe taps and CGEvent clicks don't reach the simulator on the agent Mac; XCUITest does.
- **PRs wait on one script.** `scripts/pr-ship.ts [--merge]` waits for CI and for Codex's first review, lists failing checks and unresolved review threads, reports a conflict with master, and merges when green. It exits before the 600-second tool limit with a code that names the next step, so an agent reruns it instead of writing `sleep` loops a hook blocks. Codex reviews only when a PR opens, and its summary's unresolved-findings flag never clears, so findings come from the review threads.
- **CI pins env-manager and fails on reader drift.** `.github/actions/setup/action.yml` pins the env-manager commit that Stefan's machine runs from `~/code/env-manager`. CI fails when `env-manager gen --local` changes any tracked file, so a reader-format change gets a pin bump and the regenerated readers committed together.
- **Git hooks are never skipped.** A Claude Code hook in `.claude/settings.json` blocks `--no-verify` and lefthook overrides. A failing hook gets its cause fixed; a flaky test is a bad test.
- **The orchestrator runs jobs as T3 child tasks.** `task-orchestrator-start` launches each job with `delegate_task` in its own worktree, so Stefan sees one thread instead of one per job. Every brief points the child at the skill's shared `brief.md`, so the worker rules live in one file. Each child owns its job through the merge: it drives its PR with `scripts/pr-ship.ts --merge` and never ends its turn while the PR is open. Migration PRs serialize on their own because they conflict in the drizzle journal. A child reports to the orchestrator only when it finishes or needs input. The orchestrator works the followups its children file in the same run, runs every job in parallel with no count cap, since this Mac runs 5+ jobs with their own simulators. Shared files and migrations don't serialize jobs, because a child rebases when `pr-ship` reports a conflict with master and the second migration PR regenerates its migration; a job waits only when it needs another job's result. On each wake it checks every running job's status, because a provider error can end a child's run without a notification, and rereads the scope's tasks so new ones join without being asked. Children read `brief.md` from their own worktree instead of receiving a pasted copy.
