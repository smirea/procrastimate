# API and database types

How the server's database, its HTTP endpoints, and every client share one set of types.

## Database

- **Drizzle is the source of truth.** `shared/db/schema.ts` defines every table once in `pg-core`, and `server/src/db/auth-schema.ts` defines Better Auth's. Every type that is a row, or part of one, comes from them: `Task`, `Project`, `Section`, `Label`, `Comment`, and `Settings` in `shared/model.ts` are a row's columns without `user_id`, and a `RowWrite` carries a kind, an id, and a partial of those columns.
- **Synced and server-only tables.** `SYNCED_TABLES` (`tasks`, `projects`, `sections`, `labels`, `comments`, `reads`, `settings`, `access`) are in the PowerSync publication and generated for the clients. `log` (with the client behind each write), `push`, `ramble_usage`, `ramble_budget`, `shares`, `api_tokens`, `images`, and Better Auth's never leave the server. People are Better Auth's `user` rows. Epoch milliseconds are `bigint` read as numbers, JSON columns are `jsonb`, fractional order is `double precision`, and image bytes are `bytea`.
- **Zod only for what a column cannot say.** `shared/values.ts` holds the shapes stored inside JSON columns (`Due`, `Recurrence`, `Reminder`) and the narrower values of plain columns (`Priority`, `DateKey`). `shared/db/json.ts` maps each such column to its shape, and the tables take their TypeScript types from it, so each shape is stated once. Values no table stores, such as `AuthMethods`, are Zod.
- **Row schemas are generated.** `scripts/generate` reads the tables and writes `shared/db/generated/zod.ts`, one plain Zod object per table, which the upload route parses every write with. drizzle-zod would derive the same at runtime, but it pulls all of Zod and part of Drizzle into the web bundle.
- **Client tables are generated too.** From the same schema, `scripts/generate/tables.ts` writes the web's `sqlite-core` mirrors and PowerSync schema and the Swift row types with their GRDB conformances and PowerSync schema: the same table and column names, `jsonb` as JSON text, booleans and integers as `integer`, `double precision` as `real`, a text `id` primary key and no composite keys.
- **Every table is per user.** Each table but `ramble_budget`, `access`, and Better Auth's has a `user_id` column, the owner of the space. `reads` and `settings` are keyed by `(user_id, id)`; the other synced tables by `id` alone.
- **Queries go through Drizzle.** Feature code takes a `Db` (`server/src/db/postgres.ts`) and never sees the driver: postgres.js in the Bun server and over Hyperdrive on the Worker, PGlite in tests. Row level security is on for every table with no policies, so only the server's own connection reads them.
- **Better Auth runs on Drizzle.** Its Drizzle adapter with `provider: 'pg'` over the same database and migrations, `bearer()` for the iOS token, and `session.cookieCache` so a request trusts the signed cookie for five minutes before reading the session row again.
- **Migrations.** drizzle-kit writes them, `scripts/generate` bundles them, and `server/src/db/migrate.ts` applies them under an advisory lock. CI fails when the schema has changed without a migration, and the history only grows ([Persistence](persistence.md#the-server-database)).
- **Tests use a real database.** Server tests run on PGlite through the real migrations, behind the same `handle` the Worker serves (`server/src/test-app.ts`).

## Endpoints

- **One oRPC v2 contract.** `shared/api/contract.ts` declares every HTTP endpoint with its method and path (oRPC's `openapi` meta), input, output, and typed errors, as one `contract` the Worker implements in `server/src/router.ts`. `agentContract` is the subset an AI account or a guest may call, from which the agent docs and their OpenAPI are generated. There are no internal routes: the `Account` object and its forwarding are gone.
- **Paths stay REST-like.** The contract keeps the `/api/...` paths, so the OpenAPI document reads like the API and iOS calls plain URLs. `?space=` names another user's space on the agent routes; without it a request is for the caller's own, which for an AI account is its owner's.
- **Validation is the contract's.** oRPC rejects an invalid input with a `400` and checks every output on the way out. Errors are oRPC's JSON body (`code`, `message`, `data`) with the usual status codes. Every error the server answers outside an oRPC handler uses the same body through `server/src/errors.ts`. The one exception by design is `POST /api/upload`, whose `writes` is a list of unknown values parsed one by one, so one bad write is refused alone ([Sync](sync.md)).
- **Outside the contract.** Better Auth's `/api/auth/*` routes (except `/api/auth/methods`), the PowerSync proxy `/api/powersync/*`, Ramble's WebSocket `/api/ramble/socket`, the Sentry tunnel, and image uploads (`PUT /api/images`) stay outside it. A streamed proxy, a WebSocket upgrade, and a raw binary body are not things oRPC or OpenAPI can describe. See [Task images](images.md).
- **Who may call what.** `requireActor` resolves a session or a `pm.<ownerId>.<secret>` token, `requireHuman` refuses AI accounts, and the agent routes load the space and ask `accessOf`. There is no list of shared routes any more: a route that accepts guests says so by loading the space.

## Generated types

- **One generator.** `bun run generate` (`scripts/generate/index.ts`) writes the row schemas, the bundled migrations, the client tables, the OpenAPI documents, the web's contract, the Swift API types, and the iOS colors from `app-web/src/index.css`, and rewrites a file only when its content changes. Every output lives in a git-ignored `generated` folder, which oxlint and oxfmt also ignore. Nothing generated is committed: each entry point writes the files first. `bun run start` runs it in watch mode next to the server and client; the web and server workspace scripts, root `check`, `bun test` (a preload), `scripts/setup-worktree.ts`, the iOS launcher and archive script, and Core's Xcode build phase run it before they read anything.
- **One model for every client.** A type more than one client needs is defined once, as a table in `shared/db/schema.ts` or a Zod schema next to the code that makes it, with an `id` in Zod's registry (`.meta({ id })`). TypeScript types are `z.infer` of it, and Swift types are generated from it, so neither client restates a shape.
- **OpenAPI.** `shared/api/generated/openapi.json` is the contract as OpenAPI 3.1, with the named schemas as components. `shared/api/generated/agent-openapi.json` is `agentContract` alone, which the Worker serves to AI accounts at `/api/docs/openapi`.
- **Web.** The web client calls the API through a `JsonifiedClient<RouterContractClient>` typed straight from the contract. At runtime it ships only `app-web/src/lib/generated/contract.json`, the contract's routes without their schemas.
- **iOS.** `scripts/generate/swift.ts` writes `app-ios/Sources/Core/Generated/API.swift` from every named schema plus one `API.Endpoints` descriptor per operation, and the row types with their GRDB conformances next to it. The Swift shapes (`x-flatten`, `x-inline`, `x-enum-names`, `x-epoch-ms`, `x-table` defaults, validation through `JSONDecoder.validating()`) are documented in [iOS app](ios.md).
