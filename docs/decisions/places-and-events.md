# Places and events

- **Two triggers besides dates.** A task can hang off a place (`location`) or a calendar event (`event`), or both. Each is one nullable synced field on the task, in `shared/values.ts`. The rules live in `shared/triggers.ts`, ported to Core's `Triggers`.
- **Set on iPhone only.** Only iOS can watch places and read the calendar, so only iOS sets, changes, or removes them. The web shows both read-only: row labels, details chips, and the sidebar sections. They are set with their chips in task details and in quick add, never from typed or spoken phrases, because a place or an event is picked from a list. The one exception is quick add on a place or event screen, which copies that screen's place or event onto the new task on every client, the web included, as the screen's earliest open task holds it. In quick add a picked event hides the date and repeat chips and clears any typed date or repeat on save.
- **A place.** An Apple Maps result: name, address, coordinates, a radius in meters fitted to the result, and a trigger: `arrive` notifies on entering, `leave` on exiting, and `during` shows a Live Activity with the task while there. Tasks within about 11 meters of each other share a place (`placeKey`), whatever each one named it.
- **The radius fits the place.** iOS derives it once, at pick time, from the Apple Maps extent of the result (`placeRadius` in Core's `Triggers`): a shop, address, or pin keeps 150 m, and a park, neighborhood, city, or region gets half the shorter side of its extent, so arriving in a city fires at its edge. Maps frames every point result in about a kilometer, so an extent up to 1.5 km counts as a point. It caps at 100 km and at the largest circle the device can watch (`maximumRegionMonitoringDistance`). A search that resolves to several items keeps 150 m, because its extent spans all of them. The radius is stored on the task, so changing the rule never moves existing places.
- **The radius is adjustable on iPhone.** Under the current place's map, the Location sheet offers `Block` (150 m), `Neighborhood` (1 km), and `City` (10 km), and a slider on a log scale from 100 m to 100 km (or the device maximum) that snaps to 10 m, 100 m, or 1 km steps (`Triggers.radius(atSlider:max:)`). The circle and the map's framing follow while dragging, and the radius saves when the drag ends, so a drag is one synced change. The fitted radius is kept beside it on the place (`fittedRadius`), so a `Fitted` preset leads the others and goes back to the Apple Maps size. It shows only while the radius differs from it and it is none of the fixed presets, and once shown it stays until the sheet closes, so tapping it never pulls it from under the finger. Places picked before it was stored have none and offer no `Fitted`. The web shows the radius after the place (`While at Tiergarten 1.5 km`, `formatRadius`) but does not edit it, because it has no map to show the circle on and cannot know the iPhone's maximum, and places stay set on iPhone only.
- **A place iOS won't watch says so.** `PlaceMonitor` records when iOS reports a condition `.unmonitored` (too large, past the device's region limit, or no region monitoring, as on the simulator) and when a place loses to the 20 armed soonest. Either one turns the place chip's pin into an amber warning and adds a note under the radius in the Location sheet, and is logged under the `places` category. Saving is never blocked. A place not armed yet, because its due day or first reminder is still ahead, is waiting rather than failing and shows nothing.
- **A due date at a place.** A task can have both, and then the due date says when and the place is the nudge, so the due time never notifies on its own. Reminders still fire. A single task at a place goes overdue like any task. A repeating task at a place never goes overdue: lists skip it forward to the first occurrence from today, and completing it steps from there as usual.
- **An event.** A calendar event: EventKit's external id, its title, whether it is all day, and an edge with an offset: `minutes` before the start, the start, during, or `minutes` after the end. The task's moment is that edge on its occurrence. An event replaces the due date and the repeat, so setting one clears both, and the date and repeat pickers hide while it is set.
- **Series or single.** A task on a repeating event follows the series by default and lists its upcoming occurrences, up to 10 within 60 days. It can be pinned to one occurrence instead. Every stored occurrence keeps its original start (EventKit's occurrence date), which stays put when the occurrence moves, so it is found again. A single event goes overdue once its day passes. A series skips occurrences whose day is over, so it never goes overdue. Completing a task on a series drops the occurrence it is on, and any missed before it, and rolls to the next listed one with fresh subtasks. With none left it completes.
- **The calendar is the source of event times.** iOS rewrites each open event task's title and occurrences from the calendar whenever it changes, on launch, on foreground, and in background refresh, and writes only what changed. Every client and the push server then read current times from the synced copy, so a moved event moves its task and its reminders. Relative reminders count back from the event moment. An all-day event never notifies at its moment, like a date with no time.
- **Lists.** Inbox places an event task on its moment's day and time, and a repeating place task on its skipped-forward day. Projects and labels sort an event task by its first listed occurrence.
- **Event row label.** A row reads `4:15pm ([repeat] 15m after [calendar] Standup)`: the task's moment in its due tone, then the event in muted gray. `eventLabel` in `shared/triggers.ts` returns its three parts: `when`, the lead (`Nm before`, `Start of`, `During`, `Nm after`, or `After`), and the event title. The repeat icon shows only when the task follows a series. `when` is the task's moment, the edge applied to the current occurrence, not the event start, because the colored slot reads as when the task happens on every other row. It is worded like any due date (`formatDue`), except that today has no day, as in `4:15pm`: `Tomorrow 2pm`, `Tuesday 8:30am`, `Oct 21 6pm`. An all-day event has no time. A row keeps its day even under a day heading, because the heading is easy to lose in a long list. With nothing left, the row shows only the gray event part.
- **Sidebar.** Places and Events are sections above Labels, each shown only while an open task has one. A place row is named after its earliest open task. Events sort by their next occurrence. Each row opens a list of its open tasks, subtasks included, like a label.
- **Old iOS builds.** The server defaults both fields to none on a create that lacks them, so a task made on an iOS build from before this change is not dropped.
