# Production hosting

- **One Cloudflare Worker on the free plan.** It serves the built client as static assets and runs `server/src/api.ts` for `/api/*` through `server/src/worker.ts`, the entry that wraps the handler, the crons, and the `Ramble` object in Sentry, so the browser talks to one origin in production too. `wrangler.jsonc` at the repo root configures it.
- **Production URL is `https://procrastimate.stf.lol`.** It is a Workers Custom Domain on Stefan's `stf.lol` zone, in the same Cloudflare account as the Worker. `wrangler deploy` creates its DNS record and certificate. The `workers.dev` URL stays on as a fallback.
- **Static SPA plus a Worker API, not `adapter-cloudflare`.** The client has no server rendering. With `adapter-static`, `not_found_handling: "single-page-application"`, and `run_worker_first: ["/api/*"]`, pages and assets are served without invoking the Worker. Only API calls run code.
- **Postgres on Supabase, as plain Postgres.** Project `procrastimate-prod` in us-east-1, only the database: no Supabase Auth, REST API, or Realtime. Every table has row level security on and no policies. The Worker reaches it through the Hyperdrive config `612c9ca80e5a4c90ace80c20648903c6` (binding `HYPERDRIVE`), which pools the connections near the database; the code opens a postgres.js client per request on its connection string and ends it after the response. A Neon compute would never sleep while PowerSync holds its replication slot, so Neon would bill around the clock.
- **Hyperdrive's query cache is off** (`wrangler hyperdrive update … --caching-disabled` on `procrastimate-prod`). It is on by default and serves a `SELECT` outside a transaction from cache for 60 s plus 15 s stale, which here would send a push twice from a stale `push` read, answer `No such target` for a task made in the last minute, keep a deleted API token working, and show an agent stale data after its own writes. Hyperdrive is kept for the connection pooling only.
- **Smart Placement.** `"placement": { "mode": "smart" }` runs the Worker near Postgres: an upload is a run of sequential queries, and each one crosses that distance.
- **PowerSync Cloud syncs.** Instance `procrastimate-prod` (`6ad3efdb3b1803753bd28fbf`) replicates the `powersync` publication through the database's direct host as `powersync_role`, and `procrastimate-dev` does the same for the dev database. Their configs are `powersync/prod/` and `powersync/dev/` (a `service.yaml` with the public token key inline and a `cli.yaml` with the instance ids), sharing `powersync/sync-config.yaml`, deployed with the PowerSync CLI. The Worker's `POWERSYNC_URL` var names the prod instance; the Bun dev server takes dev's from env-manager.
- **The `Ramble` Durable Object.** The one object left, named by the user id, hosts only Ramble's transcription socket, because an object's CPU budget resets per WebSocket message and its memory counts the user's open sessions ([Ramble](ramble.md)). The `Account` object is gone; the `v4` migration deletes its class.
- **Two Cron Triggers.** `* * * * *` delivers the due Web Push notifications from the `push` rows ([Push notifications](push-notifications.md)). `0 9 * * *` dumps every table through Drizzle into the `procrastimate-backups` R2 bucket as `postgres/<YYYY-MM-DD>.json`, deletes all but the newest 30, then sweeps the orphaned image bytes ([Task images](images.md)). It prunes by count, not age, so a stretch of failed runs never deletes the last good backups. Image bytes go into the dump as base64 encoded in 32 KB slices, because spreading a whole image into `String.fromCharCode` overflows V8's call stack past about 125 KB. The dump is still one string in the Worker's 128 MB, which the `log` table grows toward; a multipart R2 upload per table is the step when that gets close. Sentry cron monitors `push-delivery` and `postgres-backup` flag a run that fails or never reports. GitHub Actions was ruled out for backups because the repo is public. To restore, fetch the dump with `wrangler r2 object get` and insert its rows through Drizzle, or import the JSON with Supabase's tooling.
- **Free-tier fit.** Static asset requests are free and unlimited. Only `/api/*` counts against the 100,000 requests a day: uploads after each edit, a token every five minutes per open client, and the PowerSync stream through the proxy, one long request per device. The minute cron is 1,440 requests a day. The Worker bundle is about 3.9 MiB before compression and about 720 KiB gzipped, against the free plan's 3 MiB compressed limit.
- **API paths are the same everywhere.** Routes are mounted at `/api/*` in the handler itself. The Vite proxy forwards `/api` unchanged, and native clients call `API_URL` plus `/api/...`.
- **Deploys run from GitHub Actions.** `.github/workflows/ci.yml` runs on every pull request and every push to `master`. A `checks` job typechecks, runs unit tests on PGlite, builds, and validates the Worker bundle with `wrangler deploy --dry-run`. In parallel the end-to-end job starts the same Docker Postgres and PowerSync a worktree runs (`scripts/ci-stack.ts`) and runs Playwright against `wrangler dev` serving the build. On a push to `master`, `wrangler deploy` runs only after all of them pass.
- **All secrets live in env-manager, online.** env-manager project `procrastinate` in AWS Secrets Manager is the source of truth. Two environments: `prod` for the Worker and deploys, `dev` for local development against the dev Supabase and PowerSync. The schema is not in local mode, so `up` and `down` talk to AWS. Every Worker secret sits in the root `.env` schema's `server` scope as an optional field, so `env-manager gen --local` still builds from the schema defaults where there are no AWS credentials. `config.ts`, not the schema, decides what is required. The deploy, TestFlight, Supabase (`SUPABASE_ACCESS_TOKEN`), PowerSync Cloud (`POWERSYNC_ADMIN_TOKEN`, `POWERSYNC_DATABASE_PASSWORD`), and agent credentials sit in the `scripts` target. `server/scripts/secrets.ts` is the only bridge out: `bun run secrets:push` uploads the set `prod` Worker secrets with `wrangler secret bulk`, `bun run secrets:github` mirrors the deploy credentials to GitHub, and `bun run secrets:check` reports drift by name. It never prints a value and never deletes a secret.
- **Worker secrets.** `BETTER_AUTH_SECRET`, `POWERSYNC_JWT_PRIVATE_KEY`, `VAPID_PUBLIC_KEY`, and `VAPID_PRIVATE_KEY` are required (`REQUIRED_WORKER_SECRETS`); a missing one makes every request fail with `500` and the Worker log names the key. `ELEVENLABS_API_KEY` and the Google and Apple credentials are optional; optional providers are all or nothing. `DATABASE_URL` is never a Worker secret: the Worker has the Hyperdrive binding. `POWERSYNC_URL` is a plain var in `wrangler.jsonc`.
- **Configuration is parsed once, at the boundary.** `server/src/config.ts` turns the raw bindings into a typed `Config` once per bindings object; `worker.ts` parses it before routing and the Bun server before listening. Feature code reads `app.config`, never `env.X`. There is no ephemeral mode any more: local and CI run real local services, and the Bun entry and `.dev.vars` supply local stand-ins for the secrets env-manager leaves empty (the committed dev signing key, a fixed auth secret, a fresh VAPID pair, and `AUTH_RATE_LIMIT=off`).
- **A deploy checks the Worker's secrets first.** Before `wrangler deploy`, CI runs `bun server/scripts/secrets.ts verify`, which lists the Worker's secret names and fails when a required one is missing. It needs only the Cloudflare credentials, so CI still has no AWS access.
- **`wrangler dev` runs against the worktree's stack.** `bun scripts/wrangler-dev.ts` reads `.env.override`, points the Hyperdrive binding at the worktree's database through `CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE`, passes its PowerSync as `--var POWERSYNC_URL`, turns the sign-in rate limit off, and writes `.dev.vars` when it is missing. `bun run preview` and the e2e suite's Worker mode go through it.
- **One version for every client: `<increment>.<yyyyMMdd>`.** `scripts/app-version.mts` reads it from `HEAD`: the commit count, then the commit's UTC date, such as `465.20261017`. A web deploy and a TestFlight build of the same commit show the same version. Vite defines it as `__APP_VERSION__`; iOS writes it into its Info.plists from Core's Generate phase (see [iOS app](ios.md)). A shallow clone would count only the commits it fetched, so every CI checkout that builds fetches full history. The Sentry release stays the commit SHA.
- **Hashed assets are cached forever.** `app-web/static/_headers` marks `/_app/immutable/*` as immutable.
- **ElevenLabs secret.** `ELEVENLABS_API_KEY` is a Worker secret for Ramble's transcription proxy, kept in env-manager `prod` and `dev`. `/api/ramble/socket` answers `503` without it. `RAMBLE_UPSTREAM=cassette` is a dev and test var, never a Worker secret.
