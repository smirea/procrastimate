# Production hosting

- **One Cloudflare Worker and one Durable Object, on the free plan.** The Worker serves the built client as static assets and forwards `/api/*` to the `App` Durable Object (`server/src/worker.ts`, named `main` in `server/src/app-stub.ts`), which runs `server/src/api.ts` over the database in its SQLite storage and holds the sync sockets, hibernating, with `ping` answered without waking it (`server/src/app-object.ts`). Every user's data lives in that one object ([Sync](sync.md#server)), which runs one request at a time and needs no locks. The object is created where the first request comes from and stays there; nothing pins it. The Worker keeps Ramble's socket off it: it asks `App` who the request is (`/internal/actor`, a path the Worker never forwards from outside) and hands the upgrade to the user's `Ramble` object. Both objects and the crons run under Sentry. `wrangler.jsonc` at the repo root configures it.
- **Production URL is `https://procrastimate.stf.lol`.** It is a Workers Custom Domain on Stefan's `stf.lol` zone, in the same Cloudflare account as the Worker. `wrangler deploy` creates its DNS record and certificate. The `workers.dev` URL stays on as a fallback.
- **Static SPA plus a Worker API, not `adapter-cloudflare`.** The client has no server rendering. With `adapter-static`, `not_found_handling: "single-page-application"`, and `run_worker_first: ["/api/*"]`, pages and assets are served without invoking the Worker. Only API calls run code.
- **Supabase and PowerSync Cloud are retired.** Production ran on Supabase Postgres (`procrastimate-prod`), PowerSync Cloud (`procrastimate-prod` and `procrastimate-dev`), and Hyperdrive until the sync-engine move. Their data was imported into the `App` object ([Persistence](persistence.md#the-server-database)), and nothing reads them any more; deleting the projects, the instances, and the Hyperdrive config is Stefan's call.
- **The `Ramble` Durable Object.** Named by the user id, it hosts only Ramble's transcription socket, because an object's CPU budget resets per WebSocket message and its memory counts the user's open sessions ([Ramble](ramble.md)). Its time zone, keyterm names, and daily usage come from the `App` object over internal paths (`appRambleData`).
- **Two Cron Triggers.** The Worker's `scheduled` handler forwards each to the `App` object (`/internal/cron`). `* * * * *` delivers the due Web Push notifications from the `push` rows ([Push notifications](push-notifications.md)). `0 9 * * *` dumps every table through Drizzle into the `procrastimate-backups` R2 bucket as `sqlite/<YYYY-MM-DD>.json`, deletes all but the newest 30, then sweeps the orphaned image bytes ([Task images](images.md)). It prunes by count, not age, so a stretch of failed runs never deletes the last good backups. Image bytes go into the dump as base64. The dump is one string in the object's memory, which the `log` table grows toward; a multipart R2 upload per table is the step when that gets close. Sentry cron monitors flag a run that fails or never reports. GitHub Actions was ruled out for backups because the repo is public. To restore into a new, empty object, put the dump at `restore/pending.json` in the bucket ([Persistence](persistence.md#the-server-database)).
- **Free-tier fit.** Static asset requests are free and unlimited. Only `/api/*` counts against the 100,000 Worker requests a day: a sync after each burst of edits, a periodic pull per open client, and one live socket per device, whose hibernated pings cost nothing. The minute cron is 1,440 requests a day. The object's storage is SQLite on the free plan's Durable Object allowance, a few megabytes for this data.
- **API paths are the same everywhere.** Routes are mounted at `/api/*` in the handler itself. The Vite proxy forwards `/api` unchanged, and native clients call `API_URL` plus `/api/...`.
- **Deploys run from GitHub Actions.** `.github/workflows/ci.yml` runs on every pull request and every push to `master`. A `checks` job typechecks, runs the unit tests on in-memory SQLite, builds, and validates the Worker bundle with `wrangler deploy --dry-run`. In parallel the end-to-end job runs Playwright against `wrangler dev` serving the build, the `App` object on local SQLite included. On a push to `master`, `wrangler deploy` runs only after all of them pass.
- **All secrets live in env-manager, online.** env-manager project `procrastinate` in AWS Secrets Manager is the source of truth. Two environments: `prod` for the Worker and deploys, `dev` for local development. The schema is not in local mode, so `up` and `down` talk to AWS. Every Worker secret sits in the root `.env` schema's `server` scope as an optional field, so `env-manager gen --local` still builds from the schema defaults where there are no AWS credentials. `config.ts`, not the schema, decides what is required. The deploy, TestFlight, and agent credentials sit in the `scripts` target. `server/scripts/secrets.ts` is the only bridge out: `bun run secrets:push` uploads the set `prod` Worker secrets with `wrangler secret bulk`, `bun run secrets:github` mirrors the deploy credentials to GitHub, and `bun run secrets:check` reports drift by name. It never prints a value and never deletes a secret.
- **Worker secrets.** `BETTER_AUTH_SECRET`, `VAPID_PUBLIC_KEY`, and `VAPID_PRIVATE_KEY` are required (`REQUIRED_WORKER_SECRETS`); a missing one makes every request fail with `500` and the Worker log names the key. `ELEVENLABS_API_KEY` and the Google and Apple credentials are optional; optional providers are all or nothing.
- **Configuration is parsed once, at the boundary.** `server/src/config.ts` turns the raw bindings into a typed `Config` once per bindings object; `worker.ts` parses it before routing, the `App` object when it builds the app, and the Bun server before listening. Feature code reads `app.config`, never `env.X`. The Bun entry and `.dev.vars` supply local stand-ins for the secrets env-manager leaves empty (a fixed auth secret, a fresh VAPID pair, and `AUTH_RATE_LIMIT=off`).
- **A deploy checks the Worker's secrets first.** Before `wrangler deploy`, CI runs `bun server/scripts/secrets.ts verify`, which lists the Worker's secret names and fails when a required one is missing. It needs only the Cloudflare credentials, so CI still has no AWS access.
- **`wrangler dev` needs no stack.** `bun scripts/wrangler-dev.ts` turns the sign-in rate limit off and writes `.dev.vars` when it is missing; the `App` object keeps its SQLite under `.wrangler/state`. `bun run preview` and the e2e suite's Worker mode go through it.
- **One version for every client: `<increment>.<yyyyMMdd>`.** `scripts/app-version.mts` reads it from `HEAD`: the commit count, then the commit's UTC date, such as `465.20261017`. A web deploy and a TestFlight build of the same commit show the same version. Vite defines it as `__APP_VERSION__`; iOS writes it into its Info.plists from Core's Generate phase (see [iOS app](ios.md)). A shallow clone would count only the commits it fetched, so every CI checkout that builds fetches full history. The Sentry release stays the commit SHA.
- **Hashed assets are cached forever.** `app-web/static/_headers` marks `/_app/immutable/*` as immutable.
- **ElevenLabs secret.** `ELEVENLABS_API_KEY` is a Worker secret for Ramble's transcription proxy, kept in env-manager `prod` and `dev`. `/api/ramble/socket` answers `503` without it. `RAMBLE_UPSTREAM=cassette` is a dev and test var, never a Worker secret.
