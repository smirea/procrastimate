# Stack

- **Tooling.** Bun and TypeScript. Oxlint, oxfmt, and Lefthook for linting and hooks.
- **Oxlint reads `.oxlintrc.json`.** Oxlint finds only that file name, so the `oxlint.json` this repo once had never applied, and neither did `node/no-process-env` or the e2e import guard. Correctness rules are errors, suspicious and perf rules warnings. The style and pedantic categories are off: they were never in effect and flag hundreds of lines written in this code's own style. `node/no-process-env` is off only where reading the environment is the point: the generated readers, `scripts/`, `server/scripts/`, `app-web/scripts/`, `.claude/`, the Playwright config, tests, e2e specs, the vectors recorder's `VECTORS` switch, and the Bun dev server's entry, `server/src/index.ts`, whose `PROCRASTIMATE_DATABASE` and `PROCRASTIMATE_RESTORE` switches the Worker never reads. App code reads settings through its env reader. `import/namespace` is off: it resolves a package's Node entry, so it flagged `Sentry.httpClientIntegration`, which only `@sentry/sveltekit`'s browser build exports, while TypeScript checks namespace members against the right build. `import/default` is off for the same reason: it can't resolve Vite's `?worker&url` imports, which TypeScript types through `vite/client`. `unicorn/require-module-specifiers` is off because its fix deletes the `export {}` that keeps a `declare global` file a module. The pre-commit hook passes `--no-error-on-unmatched-pattern`, since oxlint exits 1 when every file it is given is ignored.
- **Web client.** Svelte 5 (runes) with SvelteKit 3 as a client-only single-page app (`ssr = false`, static adapter with an `index.html` fallback), Vite, and Tailwind CSS. Chosen for a small runtime, fine-grained reactivity, and built-in transitions and FLIP animations that suit the snappy, animated UX. React and TanStack Router are gone.
- **TypeScript versions.** The root uses TypeScript 7 for `server/` and `shared/`. `app-web/` pins TypeScript 6 because SvelteKit needs the TypeScript JS API, which TypeScript 7 does not ship. Bun's isolated linker keeps the two apart.
- **Type checking.** `bun run check` type-checks with `bun check` (Bun's Rust port of TypeScript 7, 4x faster than `tsc` on the root here and 18x faster than TypeScript 5.9 on the Raycast extension) and `svelte-check-native` (a Rust `svelte-check` that drives the root's TypeScript 7, 7x faster cold and about 80x warm than `svelte-check` on TypeScript 6). Both reported the same diagnostics as `tsc` and `svelte-check` on injected type errors and Svelte warnings. `svelte-check-native` does not report Svelte compile errors such as a second top-level `<style>`, so `vite build`, which CI runs, is the backstop for those. `bun check` runs a project's `check` script when it has one, so the scripts pass `--no-script`. Bun 1.4.3 ignores that flag and the root `check` script would call itself forever, so `.bun-version` pins CI to 1.4.4.
- **Generated env readers are committed as env-manager writes them.** oxfmt ignores the readers, so `env-manager gen --local` leaves a fresh worktree clean. Commit regenerated readers with the schema change that caused them; CI does not run env-manager.
- **Web env reader.** SvelteKit 3 reserves `src/env.ts`, so env-manager generates the web client's Node-only reader at `app-web/env.ts`. Scripts pass `--env-file=.env.local` because Bun does not auto-load env files when it runs Vite through its `node` shim.
- **Server.** One fetch handler in `server/src/api.ts` that owns every `/api/*` route. Bun.serve runs it in development, and in production the Cloudflare Worker forwards `/api/*` to the `App` Durable Object, which runs the same module (`server/src/worker.ts` and `server/src/app-object.ts`, both under Sentry). Task data lives in that object's SQLite and syncs through [sync-engine](sync.md) ([Persistence](persistence.md)).
- **Database and API.** Drizzle for every table, Better Auth's included, and an oRPC v2 contract with OpenAPI for every HTTP endpoint. Drizzle is the source of truth for every type a table stores. The web client is typed from the contract, and iOS gets generated Swift types. See [API and database types](api.md).
- **Shared domain code.** Environment-independent types and logic, including the natural-language parser, live in `shared/` so the server can reuse them.
