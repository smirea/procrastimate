# Ramble

Voice capture: Stefan talks, and Ramble turns the transcript into tasks he reviews before saving. The research, UX, test plan, cost, and build slices are in [Ramble design](../ramble-design.md).

**Status: decided.** Stefan accepted all eight recommended defaults from [Decisions for Stefan](../ramble-design.md#decisions-for-stefan): Ramble requires a paired device; no LLM until the corpus proves one is needed, then Workers AI Llama 3.3 70B; English only, with `language_code=en` pinned; "that's all" stops listening but never saves; caps of 5 minutes per session and 60 minutes per day; the ElevenLabs free plan, moving to Starter if he rambles daily; audio fixtures from the first option in the design's order, a TTS-scoped key used once on his machine, with offline Piper voices as the fallback; and spoken priority only from `priority one` to `four` and `p1` to `p4`.

- **Clients: web and iOS.** Both use the same endpoint and the same parser. The Apple Watch is excluded until its app exists; it would get a subset (hold to talk, short preview, save).
- **Precision over recall.** Ramble never sets a field Stefan did not say, never creates a project or label, and never reads ordinary words such as "project", "important", or "Tuesday's" as metadata. Every field on a drafted task must trace to a recognized spoken phrase, and the test corpus fails on any field without one.
- **Transcription is ElevenLabs Scribe v2 Realtime.** Streaming 16 kHz PCM, VAD commits, pinned English, `no_verbatim`, and up to 50 keyterms built server-side from trigger words and the most recently used project and label names. `scribe_v1` is deprecated and not used. Batch `scribe_v2` is the fallback if streaming through the proxy proves unreliable.
- **The key stays on the server.** `ELEVENLABS_API_KEY` is a Worker secret, never a `vars` entry, never in CI or the repo. Clients never connect to ElevenLabs or receive single-use tokens, which keeps the single-origin rule.
- **The proxy lives in the `Account` Durable Object.** `GET /api/ramble/socket` authenticates the device token like the realtime nudge socket and forwards audio to ElevenLabs. A Durable Object's CPU budget resets per incoming message, while a plain Worker's 10 ms free-plan budget covers a whole WebSocket. The object also holds the synced names for keyterms.
- **Ramble needs a paired device and has caps.** 5 minutes per session and 60 minutes per day, counted by the object, bound the cost of a leaked token. The caps count audio seconds streamed, not wall time, so a client that sends faster than real time cannot overspend, and open sessions share the daily budget. The day is the account's time zone, or UTC without one. The frame that reaches a cap is cut at it and the session ends with a final commit. A session past the daily cap is still accepted, only to send a `daily-limit` error with the next midnight and close, because a browser cannot read the status of a refused upgrade. Both caps are constants in `shared/ramble/protocol.ts`.
- **A thin socket protocol.** `shared/ramble/protocol.ts` holds it with zod. The client sends binary 100 ms PCM frames and one `stop`. The server sends `started` when ElevenLabs' session starts, `partial` and `committed` text, an `error` when one ends the session, and always one `ended` with the seconds used and the reason. `started` is the one addition to the design: clients show listening on it, and the latency script times it. Audio sent before it is buffered. A stop sends a manual commit only when audio went out since the last committed text, and waits up to 3 seconds for that text.
- **Off without the key, cassettes in tests.** Without `ELEVENLABS_API_KEY` the Worker answers `503`. `RAMBLE_UPSTREAM=cassette` makes the Bun dev server and `wrangler dev` replay recorded ElevenLabs sessions from `shared/fixtures/ramble-audio/` instead (`three-tasks` by default, another with `?cassette=<id>`), and Playwright sets it for both servers. The Bun dev server also uses cassettes when it has no key. It is never set in production.
- **Extraction is a deterministic spoken grammar.** `shared/ramble.ts` splits the transcript into tasks, subtasks, and notes on explicit separators, sentence boundaries, and continuation cues, reads spoken project, label, and priority phrases against existing names, and passes each task's text to the quick add parser in a `spoken` mode for dates, times, recurrence, and reminders. It runs on every partial transcript on both clients, so the preview needs no round trip. It is ported to Swift through `shared/vectors/ramble.json`.
- **Pauses are not task boundaries.** VAD commits only mark stable transcript text. Tasks split on explicit separators and punctuated sentences, and a sentence that is only attributes joins the task before it.
- **Two kinds of corpus cases.** Locked cases assert exact output and become vectors on both clients; precision cases are locked from the start. Scored cases, mostly natural rambles, gate on metric targets and move to the locked set once they pass.
- **Speech differs from typing.** In `spoken` mode `urgent`, `important`, and `!!` are not priorities, bare four-digit numbers are not times, compact units like `5m` do not apply, and a weekday with `'s` stays text. Priority comes only from `priority one` to `four` or `p1` to `p4`.
- **An LLM may only regroup sentences.** It is not used at first. If the corpus shows natural rambles segment badly, a later slice adds one call after stopping (Workers AI Llama 3.3 70B with a JSON schema) that returns groupings of verbatim sentence indices, validated and then re-parsed by the grammar, so it cannot add metadata or words.
- **Review before saving.** A live transcript with tinted phrases and a preview card per task with chips. Tap to toggle listening, or hold to talk. Tap a card to edit, `x` or swipe to discard. "That's all" stops listening but never saves. `Add <n> tasks` is one store command and one undo.
- **Transcription is the one online-only step.** Offline or unpaired, the mic explains why it is unavailable, and a session that drops keeps its transcript and drafts.
- **Measured latency.** Not yet measured with real speech: the proxy slice was built without the key. `bun server/scripts/ramble-latency.ts` streams a committed speech clip in real time and prints time to session start, speech to first partial, end of speech to the voice commit, and stop to the final commit; its median results go here. Through `wrangler dev` against a local fake ElevenLabs, the proxy itself added under 5 ms per message.
