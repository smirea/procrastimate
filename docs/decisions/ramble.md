# Ramble

Voice capture: Stefan talks, and Ramble turns the transcript into tasks he reviews before saving. The research, UX, test plan, cost, and build slices are in [Ramble design](../ramble-design.md).

**Status: decided.** Stefan accepted all eight recommended defaults from [Decisions for Stefan](../ramble-design.md#decisions-for-stefan): Ramble requires a registered device; no LLM until the corpus proves one is needed, then Workers AI Llama 3.3 70B; English only, with `language_code=en` pinned; "that's all" stops listening but never saves; caps of 5 minutes per session and 60 minutes per day; the ElevenLabs free plan, moving to Starter if he rambles daily; audio fixtures from the first option in the design's order, a TTS-scoped key used once on his machine, with offline Piper voices as the fallback; and spoken priority only from `priority one` to `four` and `p1` to `p4`.

- **Clients: web and iOS.** Both use the same endpoint and the same grammar. The multi-task list, live preview, and on-device model review are iOS only for now, by Stefan's call to leave the web out of this revamp; the web still fills quick add with one task. The Apple Watch is excluded until its app exists; it would get a subset (hold to talk, short preview, save).
- **Precision over recall.** Ramble never sets a field Stefan did not say, never creates a project or label, and never reads ordinary words such as "project", "important", or "Tuesday's" as metadata. Every field on a drafted task must trace to a recognized spoken phrase, and the test corpus fails on any field without one.
- **Dictation is Native or ElevenLabs.** Settings has one line, `Dictation`, with those two choices. Native is the default. Native means the platform turns speech into text, and the Ramble grammar below extracts tasks from that text. ElevenLabs is the server Scribe path, used when that option is selected and the device is online, and on the web when Native fails before hearing anything. With no internet connection the session uses Native, and the saved choice stays ElevenLabs. There is no other control, banner, or prompt for this.
- **Native on the web is the Web Speech API.** `SpeechRecognition`, or `webkitSpeechRecognition` where that is the name the browser exposes. The session is continuous, reports interim results, and is pinned to `en-US`. While online, a native session that fails before hearing anything, because the browser has neither constructor (Firefox, some embedded webviews) or errors at once (Brave exposes the API but fails with `network`), moves to the ElevenLabs socket. Offline there is no fallback recognizer, so the transcript field stays editable and typing or the operating system's own dictation (macOS Dictation, a keyboard microphone) still reaches the grammar. A recognition error after speech was heard, or any error offline, ends the session and keeps the text so far. Quick add then shows `Dictation stopped. You can type the task instead.`
- **Native on iOS is `SpeechAnalyzer`.** A `DictationTranscriber` for `en-US` with punctuation, volatile results, and frequent finalization. It runs entirely on the device, online or offline, so audio never leaves the phone, and its language assets download on first use. Only the microphone needs permission; it is requested when a voice session starts, and a denial is not asked again. Settings does not ask. Stopping waits until the words already heard are final, so the last of them reach the grammar. DEBUG builds read `PROCRASTIMATE_RAMBLE_AUDIO`, a path to a spoken audio file, and stream it through the same converter and analyzer instead of the microphone. The iOS 27 simulator has no speech model (`SFSpeechErrorDomain` 4, "model not installed"), so there the session logs `Dictation could not start` and quick add says it can be typed instead; a macOS run of the same calls transcribes a 12 second ramble in 0.5 s, first words after 0.18 s.
- **ElevenLabs Scribe v2 Realtime is the server path.** Streaming 16 kHz PCM, VAD commits, pinned English, `no_verbatim`, and up to 50 keyterms built server-side from trigger words and the most recently used project and label names. `scribe_v1` is deprecated and not used. Batch `scribe_v2` is the fallback if streaming through the proxy proves unreliable. The Ramble client opens this socket only for the `socket` capture from `voiceCapture` in `shared/dictation.ts`.
- **The key stays on the server.** `ELEVENLABS_API_KEY` is a Worker secret, never a `vars` entry, never in CI or the repo. Clients never connect to ElevenLabs or receive single-use tokens, which keeps the single-origin rule.
- **The proxy lives in the `Account` Durable Object.** `GET /api/ramble/socket` authenticates the signed-in session like the realtime nudge socket and forwards audio to ElevenLabs. A Durable Object's CPU budget resets per incoming message, while a plain Worker's 10 ms free-plan budget covers a whole WebSocket. The object also holds the synced names for keyterms.
- **Ramble needs a registered device and has caps.** 5 minutes per session and 60 minutes per day, counted by the object, bound the cost of a leaked token. The caps count audio seconds streamed, not wall time, so a client that sends faster than real time cannot overspend, and open sessions share the daily budget. The day is the account's time zone, or UTC without one. A session open across midnight stores the seconds streamed before midnight on that day and charges what follows to the new one. A socket that sends nothing for a minute ends with `idle`, so a dropped client does not hold the object open and a pause never counts as the session cap. The frame that reaches a cap is cut at it and the session ends with a final commit. A session past the daily cap is still accepted, only to send a `daily-limit` error with the next midnight and close, because a browser cannot read the status of a refused upgrade. Both caps are constants in `shared/ramble/protocol.ts`. With Turso, the seconds live on a ledger for that user and are written to `ramble_usage` when they are recorded, including after the socket upgrade has already flushed, so the next request still sees them. Without Turso they stay in the account store, which is the object's SQLite on the Worker and memory in the Bun dev server.
- **A global daily ElevenLabs budget.** On top of the per-user cap, the Worker reserves at most two hours of audio per UTC day for every account together, in Turso, when a session starts, and returns what the session did not stream when it ends. It is on only when Ramble is calling ElevenLabs and Turso is configured. A session that would exceed it is refused with the same `daily-limit` error and the next UTC midnight. If the budget cannot be recorded, Ramble answers `503` and does not open the upstream socket. Two hours covers one account using its own 60 minutes on both sides of UTC midnight, and it stops further accounts from multiplying the spend.
- **A thin socket protocol.** `shared/ramble/protocol.ts` holds it with zod. The client sends binary 100 ms PCM frames and one `stop`. The server sends `started` when ElevenLabs' session starts, `partial` and `committed` text, an `error` when one ends the session, and always one `ended` with the seconds used and the reason. `started` is the one addition to the design: clients show listening on it, and the latency script times it. Audio sent before it is buffered. A stop sends a manual commit only when audio went out since the last committed text, and waits up to 3 seconds for that text.
- **Off without the key, cassettes in tests.** Without `ELEVENLABS_API_KEY` the Worker answers `503`. `RAMBLE_UPSTREAM=cassette` makes the Bun dev server and `wrangler dev` replay recorded ElevenLabs sessions from `shared/fixtures/ramble-audio/` instead (`three-tasks` by default, another with `?cassette=<id>`), and Playwright sets it for both servers. The Bun dev server also uses cassettes when it has no key. It is never set in production.
- **Extraction is a deterministic spoken grammar.** `shared/ramble.ts` splits the transcript into tasks, subtasks, and notes on explicit separators, sentence boundaries, continuation cues, and list intros (`with subtasks`, `the steps are`, `which means`, `that means`, `the list is`, or a colon after a word), reads spoken project, label, and priority phrases against existing names, and passes each task's text to the quick add parser in a `spoken` mode for dates, times, recurrence, and reminders. It runs on the device when listening stops, so the chips need no round trip. Its vectors are `shared/vectors/ramble.json`.
- **Spoken corrections keep only the new phrase.** `Thursday, actually make that Friday`, `the 20th, I mean the 21st`, `today, no wait, tomorrow`, and `priority 2, actually priority 1` are rewritten to the second phrase before parsing, so the corrected words never reach the title. A correction that names only a time keeps the date: `tomorrow at 3pm sorry 4pm` is tomorrow at 4pm. `scratch that` alone still drops the current task.
- **The Swift grammar is `Core/Ramble.swift`.** Linux `VectorTests` runs `ramble.json`. Spoken mode is already in the Swift quick add parser, because `quick-add` is ported and its vectors include speech.
- **Ramble is the mic in quick add.** After Add, the textbox shows a mic on its right. The mic hides once the user types. Tapping it records, and the icon becomes stop. The live transcript fills the textbox. On the web, stopping replaces it with the parsed title and fills the chips; several tasks become one title. On iOS:
  - **Live.** The grammar runs off the main thread on every transcript update, and the spoken tasks, with their subtasks, dates, and other fields, show under the textbox as Stefan talks. It costs 3 to 18 ms per full ramble in a release build.
  - **Review on stop.** Apple's on-device model (`SystemLanguageModel`, Foundation Models) reviews the grammar's tasks, then `Ramble.reviewed` applies what the transcript backs up. A spinner shows while it runs, with a 4 second limit. When the model is unavailable, fails, or is slow, the grammar's tasks stand.
  - **One plain task fills the field.** A single task with no subtasks or notes goes into the textbox and chips, to edit like typed text. Anything more stays as a list with a remove button per task and subtask and `Add N tasks`, which saves every task with its subtasks and notes. List defaults fill only a field the speech left empty, and subtasks take none.
  - "That's all" stops listening and does not save. There is no separate sheet, no hold-to-talk, no long-press, and no Shift+Q.
- **The on-device model only restructures.** It sees the grammar's numbered draft and returns, per task, a role (`task`, `subtaskOfPrevious`, `partOfPrevious`, `takenBack`) and any items it reads inside the title. Dates, priorities, projects, labels, and reminders always come from the grammar, so the model cannot invent them, and every kept item must appear in the title. `Ramble.reviewed` keeps two verdicts:
  - **Items become subtasks** with two or more items, all in the title, set off from a lead of two or more words by a comma or colon (`Buy groceries for the party, milk, eggs and bread`). `Buy a phone case and a screen protector` stays one task.
  - **A task nests under the one before** only when that one already has subtasks and no sentence end or `next task` lies between them.
  - The other roles are ignored. On the eval they turned real tasks into subtasks or dropped them.
- **Why this model, and the numbers.** Apple's on-device model is free, private, works offline, and needs no server. Asked to copy tasks out of the transcript itself, it dropped tasks and invented fields; labelling clauses was right about 65% of the time. Reviewing the grammar's draft with the guards above, on a hand-labelled set of 30 messy rambles (`/tmp`-only harness, cases in the PR), exact structure went from 12 (old grammar) to 19 (grammar with corrections and list intros) to 22 (with the model), with a median of 0.9 s and p90 of 1.25 s on AFM 3 Core Advanced. On the 447 corpus vectors the model changed nothing after the guards. iOS 27's Private Cloud Compute model is larger, but it needs a managed entitlement from Apple and does not run in simulators, so it waits for that entitlement.
- **The model's guardrails are `permissiveContentTransformations`.** The content is Stefan's own speech, and the default guardrails failed in the simulator and can refuse ordinary tasks.
- **Start Ramble opens quick add already recording.** The iOS intent and its shortcut do that. The mic in the textbox is the other way in.
- **The web socket authenticates like sync.** The page sends `procrastimate.ramble` and `device.<id>` as subprotocols, and the session cookie goes with the upgrade. iOS sends `Authorization: Bearer`, the `procrastimate.ramble` subprotocol, and the `x-procrastimate-device` header. Before this, iOS sent `procrastinate.ramble` and `x-procrastinate-device`, so the server found no device and refused every iOS ElevenLabs session. A signed-in install can open the mic.
- **Pauses are not task boundaries.** VAD commits only mark stable transcript text. Tasks split on explicit separators and punctuated sentences, and a sentence that is only attributes joins the task before it.
- **Two kinds of corpus cases.** Locked cases assert exact output and become vectors on both clients; precision cases are locked from the start. Scored cases, mostly natural rambles, gate on metric targets and move to the locked set once they pass.
- **Speech differs from typing.** In `spoken` mode `urgent`, `important`, and `!!` are not priorities, bare four-digit numbers are not times, compact units like `5m` do not apply, and a weekday with `'s` stays text. Priority comes only from `priority one` to `four` or `p1` to `p4`.
- **Stefan accepted the design's defaults.** Paired device, no server LLM unless the natural-ramble score stays under 90% (the on-device model above is a free, private review step, not that slice), English only, "that's all" stops listening and does not save, 5 minutes per session and 60 per day, and priority only from `priority one` to `four` or `p1` to `p4`.
- **Review before saving.** Nothing saves until Add task or `Add N tasks`. "That's all" stops listening and never saves.
- **The simulator speaks a script.** DEBUG builds read `PROCRASTIMATE_RAMBLE_SCRIPT` and stream it into the transcript a word at a time, then wait for stop, so a UI test drives the live list, the model review, and saving without a microphone.
- **ElevenLabs is the online-only path.** Native dictation runs on the device and works offline. A session that drops keeps its transcript and drafts. A missing key or a refused socket matters only when the capture is the ElevenLabs socket. A signed-in install can open the mic.
- **Measured latency.** Not yet measured with real speech: the proxy slice was built without the key. `bun server/scripts/ramble-latency.ts` streams a committed speech clip in real time and prints time to session start, speech to first partial, end of speech to the voice commit, and stop to the final commit; its median results go here. Through `wrangler dev` against a local fake ElevenLabs, the proxy itself added under 5 ms per message.
