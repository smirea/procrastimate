# Ramble

Voice capture: Stefan talks, and Ramble turns the transcript into tasks he reviews before saving. The research, UX, test plan, cost, and build slices are in [Ramble design](../ramble-design.md).

**Status: decided.** Stefan accepted all eight recommended defaults from [Decisions for Stefan](../ramble-design.md#decisions-for-stefan): Ramble requires a registered device; no LLM until the corpus proves one is needed, then Workers AI Llama 3.3 70B; English only, with `language_code=en` pinned; "that's all" stops listening but never saves; caps of 5 minutes per session and 60 minutes per day; the ElevenLabs free plan, moving to Starter if he rambles daily; audio fixtures from the first option in the design's order, a TTS-scoped key used once on his machine, with offline Piper voices as the fallback; and spoken priority only from `priority one` to `four` and `p1` to `p4`.

- **Clients: web and iOS.** Both use the same endpoints, the same grammar, the same Gemini outline, and the same fullscreen drawer, with the same two parsing modes. The Apple Watch is excluded until its app exists; it would get a subset (hold to talk, short preview, save).
- **Precision over recall, for names.** Ramble never creates a project or label: Gemini picks only from the names it is given, and `resolveOutline` drops any name that matches none. The grammar (commands mode, offline, and the live tail) still never sets a field Stefan did not say, and its corpus fails on any field without a spoken phrase. Smart mode follows Todoist's reading instead: "high priority" and "urgent" are P1, and a correction or a back-reference can change an earlier task.
- **Dictation is Native or ElevenLabs.** Settings has one line, `Dictation`, with those two choices. Native is the default. Native means the platform turns speech into text, and the Ramble grammar below extracts tasks from that text. ElevenLabs is the server Scribe path, used when that option is selected and the device is online, and on the web when Native fails before hearing anything. With no internet connection the session uses Native, and the saved choice stays ElevenLabs. There is no other control, banner, or prompt for this.
- **Native on the web is the Web Speech API.** `SpeechRecognition`, or `webkitSpeechRecognition` where that is the name the browser exposes. The session is continuous, reports interim results, and is pinned to `en-US`. While online, a native session that fails before hearing anything, because the browser has neither constructor (Firefox, some embedded webviews) or errors at once (Brave exposes the API but fails with `network`), moves to the ElevenLabs socket. Offline there is no fallback recognizer, so the transcript field stays editable and typing or the operating system's own dictation (macOS Dictation, a keyboard microphone) still reaches the grammar. A recognition error after speech was heard, or any error offline, ends the session and keeps the text so far. Quick add then shows `Dictation stopped. You can type the task instead.`
- **Native on iOS is `SpeechAnalyzer`.** A `DictationTranscriber` for `en-US` with punctuation, volatile results, and frequent finalization. It runs entirely on the device, online or offline, so audio never leaves the phone, and its language assets download on first use. Only the microphone needs permission; it is requested when a voice session starts, and a denial is not asked again. Settings does not ask. Stopping waits until the words already heard are final, so the last of them reach the grammar. DEBUG builds read `PROCRASTIMATE_RAMBLE_AUDIO`, a path to a spoken audio file, and stream it through the same converter and analyzer instead of the microphone. The iOS 27 simulator has no speech model (`SFSpeechErrorDomain` 4, "model not installed"), so there the session logs `Dictation could not start` and quick add says it can be typed instead; a macOS run of the same calls transcribes a 12 second ramble in 0.5 s, first words after 0.18 s.
- **ElevenLabs Scribe v2 Realtime is the server path.** Streaming 16 kHz PCM, VAD commits, pinned English, `no_verbatim`, and up to 50 keyterms built server-side from trigger words and the most recently used project and label names. The names are the same addable set the drawer offers: the user's own, and every project or label shared to them whose `access` row says `edit`, so view-only shares are never biased (`loadKeytermSource`). Recency counts the user's own tasks and the shared tasks they see, then names sort alphabetically; terms are deduped case-insensitively, names over ElevenLabs' 20 characters are skipped, and the list stops at 50. `scribe_v1` is deprecated and not used. Batch `scribe_v2` is the fallback if streaming through the proxy proves unreliable. The Ramble client opens this socket only for the `socket` capture from `voiceCapture` in `shared/dictation.ts`.
- **The key stays on the server.** `ELEVENLABS_API_KEY` is a Worker secret, never a `vars` entry, never in CI or the repo. Clients never connect to ElevenLabs or receive single-use tokens, which keeps the single-origin rule.
- **The proxy lives in the `Ramble` Durable Object.** The Worker authenticates the signed-in session on `GET /api/ramble/socket` and forwards the upgrade, with the resolved actor in a header only the Worker sets, to the user's `Ramble` object (`server/src/ramble-object.ts`), named by the user id. A Durable Object's CPU budget resets per incoming message, while a plain Worker's 10 ms free-plan budget covers a whole WebSocket. The object opens its own Postgres client over Hyperdrive, loads the keyterms and the user's time zone, and runs the session (`server/src/ramble.ts`). The Bun dev server hosts the same session code on its own WebSocket server.
- **The draft's types are schemas.** `RambleTask`, `RambleToken`, `RambleSpan`, `RambleDraft`, and `RambleTokenKind` are Zod schemas in `shared/ramble.ts` with ids, so the Swift generator writes them into `API.swift` and Core keeps no hand-written copy; the grammar's token kinds are the enum's cases.
- **Ramble needs a signed-in human and has caps.** 5 minutes per session and 60 minutes per day, counted by the object, bound the cost of a leaked token. The caps count audio seconds streamed, not wall time, so a client that sends faster than real time cannot overspend, and open sessions share the daily budget. The day is the account's time zone, or UTC without one. A session open across midnight stores the seconds streamed before midnight on that day and charges what follows to the new one. A socket that sends nothing for a minute ends with `idle`, so a dropped client does not hold the object open and a pause never counts as the session cap. The frame that reaches a cap is cut at it and the session ends with a final commit. A session past the daily cap is still accepted, only to send a `daily-limit` error with the next midnight and close, because a browser cannot read the status of a refused upgrade. Both caps are constants in `shared/ramble/protocol.ts`. The day's stored seconds are read once from `ramble_usage` into the object's one count of the user's day, which every session of that day charges and reads, so no frame costs a query and no session holds a stale copy; a session's seconds are added to the row with one atomic upsert when it ends or the day rolls, and the open sessions' tallies count in between. The cap is checked before the keyterms are read, and those come from three task columns and the names, not the whole space. The ledger and the serial queue the Turso flush needed are gone.
- **A thin socket protocol.** `shared/ramble/protocol.ts` holds it with zod. The client sends binary 100 ms PCM frames and one `stop`. The server sends `started` when ElevenLabs' session starts, `partial` and `committed` text, an `error` when one ends the session, and always one `ended` with the seconds used and the reason. `started` is the one addition to the design: clients show listening on it, and the latency script times it. Audio sent before it is buffered. A stop sends a manual commit only when audio went out since the last committed text, and waits up to 3 seconds for that text.
- **Off without the key, cassettes in tests.** Without `ELEVENLABS_API_KEY` the Worker answers `503`. `RAMBLE_UPSTREAM=cassette` makes the Bun dev server and `wrangler dev` replay recorded ElevenLabs sessions from `shared/fixtures/ramble-audio/` instead (`three-tasks` by default, another with `?cassette=<id>`), and Playwright sets it for both servers. It is never set in production.
- **The grammar is commands mode, the offline path, and the live tail.** `shared/ramble.ts` splits the transcript into tasks, subtasks, and notes on explicit separators, sentence boundaries, continuation cues, and list intros (`with subtasks`, `the steps are`, `which means`, `that means`, `the list is`, or a colon after a word), reads spoken project, label, and priority phrases against existing names, and passes each task's text to the quick add parser in a `spoken` mode for dates, times, recurrence, and reminders. It runs on the device when listening stops, so the chips need no round trip. Its vectors are `shared/vectors/ramble.json`.
- **Spoken corrections keep only the new phrase.** `Thursday, actually make that Friday`, `the 20th, I mean the 21st`, `today, no wait, tomorrow`, and `priority 2, actually priority 1` are rewritten to the second phrase before parsing, so the corrected words never reach the title. A correction that names only a time keeps the date: `tomorrow at 3pm sorry 4pm` is tomorrow at 4pm. `scratch that` alone still drops the current task.
- **The Swift grammar is `Core/Ramble.swift`.** Linux `VectorTests` runs `ramble.json`. Spoken mode is already in the Swift quick add parser, because `quick-add` is ported and its vectors include speech.
- **Ramble is a fullscreen drawer.** Stefan asked for Ramble to feel like a wonderful experience rather than text dropped into quick add, still packed with function. After Add, the textbox shows a mic on its right while it is empty. Tapping it replaces quick add with the drawer, already listening, with quick add's list defaults. Todoist's Ramble was the reference, not a template.
  - **Waveform.** Capsule bars driven by the real mic level: the newest level in the middle and older ones rippling out to both edges, settling to a row of dots at rest. It was picked over layered sine ribbons and a glow around the stop button, which were prototyped side by side: the bars read clearly as a level, match the capsule shapes, and port to SwiftUI as is. The level is written at audio rate and read once per frame (`LevelMeter`), so a loud mic never re-renders the drawer. The ElevenLabs path reads it from the PCM it streams; native speech has no level, so the web opens its own analyser on the mic and iOS reads the analyzer's tap. `waveHeights` (web) and `RambleWaveform.Wave` (iOS) are the same math.
  - **Live.** The grammar runs on every transcript update, and in smart mode Gemini's latest outline leads the list with the grammar's tasks for the words spoken since (off the main thread on iOS; 3 to 18 ms per full ramble in a release build). Tasks rise into place out of a soft blur, title words fade in one by one, and a phrase the grammar turns into a field leaves the title as its chip pops in. Rows keep their position as a key, since a ramble only grows at its end, so nothing remounts as the text grows or when listening stops. Above the waveform, the end of the transcript shows with each recognized phrase tinted by its field and spoken commands faded. Before the first task, the drawer shows three examples for the current mode. iOS gives a light haptic as each task arrives.
  - **Sorting on stop.** In smart mode the header says `Sorting the ramble…` while the final outline is read. It is skipped when the last live read already covers the final transcript, and it gives up after 6 seconds, keeping the last outline plus the grammar's tasks for the words after it.
  - **Review.** After stop every task and subtask has an editable title and a remove button. Tapping a task opens its date, priority, labels, and project pickers, and its repeat and reminders as chips that remove themselves. The mic keeps talking, and the new tasks append to the list. `Add N tasks` saves every task with its subtasks and notes in one action, shows the first in its list, and toasts the count. List defaults fill only a field the speech left empty, and subtasks take none (`rambleNewTask` and `Ramble.newTask`). With nothing heard, `Type instead` goes back to quick add.
  - **Keys and stopping.** On the web, Escape stops listening first, then closes an open editor, then closes the drawer; Space toggles listening and Enter saves when no field has focus. Closing discards the ramble. "That's all" stops listening and does not save. There is no hold-to-talk, no long-press, and no Shift+Q.
  - **Keyboard.** While a title or field is being edited, the drawer ends at the top of the on-screen keyboard (on the web through `--keyboard-inset`), so the edited row and the `Add` button stay in view.
- **Smart mode is Gemini, read while Stefan talks.** Stefan found the on-device split slow at the end, weak on parsing, and blind to Todoist-style corrections, and asked for Todoist Ramble's behavior on Gemini Flash. Todoist streams audio to Gemini Flash Live, which emits add, edit, and delete tool calls; its dates are English phrases its own parser resolves, and it has no subtasks. ProcrastiMate keeps its transcript (native or ElevenLabs) and sends the text to `POST /api/ramble/outline`, which asks Gemini for an outline: each task's title, a `when` phrase, a `reminder` phrase, a priority, an existing project and labels, notes, and subtasks three levels deep. `resolveOutline` (TS and Swift) reads the phrases with quick add and the names against existing projects and labels, so the model never does date math or picks an id.
  - **The prompt is Todoist's reading.** Corrections keep the final version; a back-reference ("make the dentist one priority one", "move the email to Monday") edits the earlier task; "scratch that", "forget the apples", and "never mind the gym" remove; restating a task updates it. Listed items become subtasks named as said ("Milk", not "Get milk"), and grouped items nest under their heading ("for food get pizza and soda"). Spans are counted in days, and times always carry am or pm. It lives in `server/src/ramble-outline.ts`.
  - **What the speaker never said is dropped.** `spokenOnly` on the server clears a project or label whose name is not in the transcript (`call the bank` is not the `calls` label) and every priority when no priority word was said (`this is important`).
  - **The model is `gemini-3.5-flash-lite` with minimal thinking.** The Lite models scored within a case or two of each other, and this one had the tightest latency.
  - **Read while talking, so stopping rarely waits.** `Outliner` (web) and `RambleOutliner` (iOS) keep one request in flight, sent after a 500 ms pause in the words or 2 seconds of nonstop speech, then the newest transcript. Stop reuses the last read when the transcript has not changed since, and otherwise asks once more. Two failed reads in a row turn the outliner off for the capture. Offline, without `GEMINI_API_KEY` (503), on a Gemini failure (502), or past the 6 second wait, the grammar's tasks stand.
  - **Switching modes rereads.** The `Smart` / `Commands` pill in the drawer's header is the synced `rambleMode` setting. Switching while listening rereads the live list; after stop it rereads the last capture and replaces its tasks, edits included.
  - **Keys.** `GEMINI_API_KEY` is a Worker secret. Dev uses a free-tier key on Google Cloud project `sage-1207`; prod uses a key on `personal-1230`, whose AI Studio prepaid credits were used up on October 23, so prod answers 502 and keeps the grammar until they are topped up. The free tier caps each model at 500 requests a day and may use the content for training, so it is not for production.
- **Commands mode reads only cues.** `parseRamble(..., { commands: true })`: `new task`, `next task`, `next one`, or `and another thing` starts a task; `subtask` (or `add a subtask`) starts a subtask; `note` or `description` adds notes until the next cue; `scratch that` drops the current one; `that's all` stops. Dates, `priority one` to `four`, and existing project and label phrases still apply. Sentences, commas, verbs, and list intros never split, so a ramble without cues is one task. It reuses the grammar and its Swift port, so both clients match through the vectors.
- **The numbers, October 23 2026.** `server/scripts/ramble-eval.ts` scores the grammar and Gemini through the production code on `shared/fixtures/ramble-eval/`: the 30 `structure`, 60 `dev`, and 30 `holdout` rambles from before, plus 50 `todoist-dev` and 30 `todoist-holdout` rambles an agent wrote blind from public Todoist Ramble examples (about a third corrections, a fifth nested). Exact means every task, subtask, and scored field matched.
  - **Old sets, before tuning** (structure / dev / holdout): grammar 19 / 32 / 8; Apple's on-device split 26 / 47 / 13 at a median 0.9 s; `gemini-3.1-flash-lite` 24 / 49 / 19; `gemini-3.5-flash-lite` low thinking 25 / 50 / 18; minimal thinking 25 / 48 / 18 at a median 0.9 s and p90 1.0 to 1.3 s.
  - **Todoist sets** (dev / holdout): grammar 11 / 6; the on-device split 15 / 6, even scored only on first-level titles and dates. `gemini-3.5-flash-lite` with the Todoist-informed prompt scored 45 on dev. After the last prompt changes and the guard below, `gemini-3.1-flash-lite` scored 43 on dev and 27 on the holdout, and 21 on the old holdout. Those last runs used 3.1 because the free tier had run out of 3.5 Flash-Lite requests for the day; the two scored within a case or two of each other everywhere they were both run. Full Flash (`gemini-3.5-flash`) waited up to 113 s in the free tier's queue and never finished a run, so it is unmeasured.
  - **Speech.** 24 Todoist rambles spoken with macOS `say`: ElevenLabs Scribe v2 transcribed them at a median 0% word error rate and 19 parsed exactly against 21 from the clean text; Apple's on-device dictation had a 9.3% error rate and 14. Sending the audio straight to Gemini, as Todoist does, scored 16 at a median 2.5 s. Dictation stays a choice in Settings, but ElevenLabs is the more accurate one.
  - **Latency** was measured on the free tier, whose queue adds seconds to the tail with no relation to length; read the medians.
- **The on-device split is gone.** Gemini matched or beat it on every set but `structure` and added no wait on top of the last live read, while the split held stop for up to 4 seconds. `RambleModel`, `RambleStructure`, and `Evals/RambleModel` were removed; `Ramble.newTask` moved to `Core/RambleNewTask.swift`. The Private Cloud Compute plan for Ramble went with them.
- **Start Ramble opens the drawer already listening.** The iOS intent and its shortcut do that. The mic in quick add is the other way in.
- **The web socket authenticates with the session.** The page sends `procrastimate.ramble` and `device.<id>` as subprotocols, and the session cookie goes with the upgrade. iOS sends `Authorization: Bearer`, the `procrastimate.ramble` subprotocol, and the `x-procrastimate-device` header. A signed-in human can open the mic; an AI account cannot.
- **Pauses are not task boundaries.** VAD commits only mark stable transcript text. Tasks split on explicit separators and punctuated sentences, and a sentence that is only attributes joins the task before it.
- **Two kinds of corpus cases.** Locked cases assert exact output and become vectors on both clients; precision cases are locked from the start. Scored cases, mostly natural rambles, gate on metric targets and move to the locked set once they pass.
- **Speech differs from typing.** In `spoken` mode `urgent`, `important`, and `!!` are not priorities, bare four-digit numbers are not times, compact units like `5m` do not apply, and a weekday with `'s` stays text. Priority comes only from `priority one` to `four` or `p1` to `p4`.
- **Stefan accepted the design's defaults.** Paired device, no server LLM unless the natural-ramble score stays under 90% (the on-device model above is a free, private structure step, not that slice), English only, "that's all" stops listening and does not save, 5 minutes per session and 60 per day, and priority only from `priority one` to `four` or `p1` to `p4`. On October 23 2026 Stefan asked for Todoist-style parsing on Gemini Flash, which replaced the "no server LLM" default; see Smart mode above.
- **Every space's names, as in quick add.** The drawer parses and its pickers list the projects and labels of every space a new task may land on, by the rule in [Quick add](quick-add.md): the user's own and anything shared to edit, never view only. Each task saves into the space its project or labels route it to, and its labels picker lists and creates in that space. It reads the same sources as quick add (`addableProjects` and `addableLabels` on the web, `Store.everySpace` and `namesFromEverySpace` on iOS); it used to read only the screen's space on iOS, and every space including view-only shares on the web.
- **Review before saving.** Nothing saves until `Add task` or `Add N tasks` in the drawer. "That's all" stops listening and never saves.
- **The simulator speaks a script.** DEBUG builds read `PROCRASTIMATE_RAMBLE_SCRIPT` and stream it into the transcript a word at a time, then wait for stop, so a UI test drives the live list, the model split, and saving without a microphone.
- **ElevenLabs is the online-only path.** Native dictation runs on the device and works offline. A session that drops keeps its transcript and drafts. A missing key or a refused socket matters only when the capture is the ElevenLabs socket. A signed-in install can open the mic.
- **Measured latency.** Not yet measured with real speech: the proxy slice was built without the key. `bun server/scripts/ramble-latency.ts` streams a committed speech clip in real time and prints time to session start, speech to first partial, end of speech to the voice commit, and stop to the final commit; its median results go here. Through `wrangler dev` against a local fake ElevenLabs, the proxy itself added under 5 ms per message.
