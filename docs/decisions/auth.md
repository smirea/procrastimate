# Auth

Sign-in is Better Auth, inside the Worker. The signed-in user owns the tasks. A device id only names the install.

- **Sessions, not device tokens.** Email and password sign-up and sign-in. No password reset, because the app does not send email. Google and Apple sign-in use the web redirect on the web and a native sheet on iOS. iOS posts the identity token to `POST /api/auth/sign-in/social`. Sessions last a year and extend after a day online, so days offline do not sign anyone out.
- **Where the session lives.** The web keeps the Better Auth cookie. It also caches the user id in `localStorage` under `procrastimate-user`, because the cookie is httpOnly and the app must open offline. iOS keeps the bearer token from `set-auth-token` in the Keychain under `procrastimate-session`. It keeps no cookies: every API request goes through `APIClient.session`, which neither stores nor sends them, because Better Auth refuses a request that carries its cookie without an `Origin` (`403 MISSING_OR_NULL_ORIGIN`), and native requests send no `Origin`. A cached session opens the app. A network failure keeps it. A `401`, or a session response with no user, clears it and shows sign-in.
- **The device id is not a secret.** It stays in the snapshot's `sync` section. The web sends it as the `device.` WebSocket subprotocol and as `x-procrastimate-device`. iOS sends that header and `Authorization: Bearer`. The Worker checks the session, or an AI account's API token, and sets `x-procrastimate-actor`, the JSON `Actor`; the space's object trusts only that. A request without the header is rejected. See [Sharing](sharing.md). The stored `token_hash` is `sha256(userId:deviceId)` so the column stays unique. It is not a credential. A revoked device stays revoked.
- **Better Auth's tables are Drizzle's.** With Turso, Better Auth runs on its Drizzle adapter over the account database, and drizzle-kit migrates its tables with the rest. See [API and database types](api.md).
- **Rate limits live in Turso.** Better Auth stores its rate limits in the database, so a new Worker isolate still enforces them. An ephemeral run signs in against the in-memory database with rate limits off.
- **One user, one account object.** The Durable Object name is the user id. Turso rows are scoped by `user_id`. `EPHEMERAL=1` leaves Turso untouched and uses an in-memory auth database with a fixed secret. See [Production hosting](production-hosting.md).
- **Switching users does not upload the previous list.** `procrastimate-owner` (web `localStorage`, iOS `UserDefaults`) remembers who the local document belongs to, including after sign-out. A different user clears tasks, projects, and labels and installs a sync section with the same device id, cursor 0, and an empty outbox, so the next sync is a snapshot pull. The first sign-in on a browser that has never had an owner uploads the local list.
- **Sign-in is the first screen only without a session.** The screen is the glass card: email and password, and Sign in with Google or Apple when `GET /api/auth/methods` says those providers are configured. Missing credentials hide the button, so CI boots without them.
- **Settings.** Delete all data stays. Sign out drops the session and keeps the local document. Delete account confirms, wipes that user's tasks, then deletes the Better Auth user. It does not ask for a password, because a social account may not have one.
- **Secrets.** `BETTER_AUTH_SECRET`, the Google client ids and secret, and the Apple Services ID, client secret, and key material live in the root `.env` schema and go out through `secrets:push`. An empty value omits that provider. See the pull request for the values Stefan obtains.
- **iOS tests.** `PROCRASTIMATE_SIGNED_IN=1` is DEBUG-only. It shows the app without a Keychain token and does not call the server. Release ignores it. App Intents keep using the local store.
