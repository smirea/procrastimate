# Auth

Sign-in is Better Auth, inside the Worker. The signed-in user owns the tasks. An install id only names the install.

- **Sessions, not device tokens.** Email and password sign-up and sign-in. No password reset, because the app does not send email. Google and Apple sign-in use the web redirect on the web and a native sheet on iOS. iOS posts the identity token to `POST /api/auth/sign-in/social`. Sessions last a year and extend after a day online, so days offline do not sign anyone out.
- **Where the session lives.** The web keeps the Better Auth cookie. It also caches the user id in `localStorage` under `procrastimate-user`, because the cookie is httpOnly and the app must open offline. iOS keeps the bearer token from `set-auth-token` in the Keychain under `procrastimate-session`. It keeps no cookies: every API request goes through `APIClient.session`, which neither stores nor sends them, because Better Auth refuses a request that carries its cookie without an `Origin` (`403 MISSING_OR_NULL_ORIGIN`), and native requests send no `Origin`. A cached session opens the app. A network failure keeps it. A `401`, or a session response with no user, clears it and shows sign-in.
- **Who a request is from.** `server/src/actor.ts` turns the session, or an AI account's `pm.<ownerId>.<secret>` bearer looked up by its SHA-256 in `api_tokens`, into the `Actor` (`{ id, name, kind, ownerId }`). `requireHuman` keeps AI accounts off the human-only routes. A session bearer, which iOS sends, is resolved once a minute per Worker isolate and cached in memory, the same trust the web's signed cookie cache gives, so a request costs no session read and a token revoked elsewhere works for at most a minute; sign-out drops it from that isolate's cache at once. There is no actor header and no forwarding any more: the Worker serves every route itself. See [Sharing](sharing.md).
- **Better Auth's tables are Drizzle's.** Better Auth runs on its Drizzle adapter with `provider: 'pg'` over the one Postgres database, and drizzle-kit migrates its tables (`server/src/db/auth-schema.ts`) with the rest. `bearer()` serves iOS, and `session.cookieCache` lets a request trust the signed cookie for five minutes before reading the session row, which saves a query on most requests. See [API and database types](api.md).
- **Rate limits live in Postgres.** Better Auth stores its rate limits in the database, so a new Worker isolate still enforces them. `AUTH_RATE_LIMIT=off` turns them off for the Bun dev server, unit tests, and the end-to-end runs, which sign up many users from one address. Production never sets it.
- **Sync tokens.** A signed-in human asks `GET /api/sync/token` for the short-lived PowerSync token; see [Sync tokens and access](sync-auth.md).
- **The install id is not a secret.** A client-made id stored device-locally, sent as `x-procrastimate-device` on the push routes and Ramble, and on a browser WebSocket as the `device.<id>` subprotocol. There is no device table, no device list, and no revoke screen; the session is the credential.
- **Switching users does not upload the previous list.** The local database remembers who it belongs to, including after sign-out: on the web in its own local-only `procrastimate_owner` table, on iOS in `procrastimate-owner` in `UserDefaults`. The web's browser storage commits with relaxed durability, so a page closed right after a commit may lose it, though never out of order; a name kept in `localStorage` once outlived a clear lost that way and showed the previous account's rows. The web still writes `procrastimate-owner` to `localStorage` after the table, only so other tabs notice the switch. A different user disconnects and clears the PowerSync database, so nothing of the previous user's uploads. The web records the new owner only once the clear worked and tries a failed clear again, so the database never belongs to someone while it holds another account's rows. Every other open tab reloads when the owner changes, since its tab still reads as the previous account. Sign out keeps the database.
- **Sign-in is the first screen only without a session.** The screen is the glass card: email and password, and Sign in with Google or Apple when `GET /api/auth/methods` says those providers are configured. Missing credentials hide the button, so CI boots without them.
- **Settings.** Delete all data deletes every own row locally, and PowerSync uploads the deletes. Sign out drops the session and keeps the local database. There is no account deletion, in the clients or on the server.
- **Secrets.** `BETTER_AUTH_SECRET`, the Google client ids and secret, and the Apple Services ID, client secret, and key material live in the root `.env` schema and go out through `secrets:push`. An empty value omits that provider. The Bun dev server and `.dev.vars` use a fixed insecure auth secret when env-manager leaves it empty.
- **iOS tests.** `PROCRASTIMATE_SIGNED_IN=1` is DEBUG-only. It shows the app without a Keychain token and does not call the server. Release ignores it. App Intents keep using the local store.
