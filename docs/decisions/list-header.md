# List header and filters

Every top-level list (Inbox, Tomorrow, This week, No date, Completed, projects, labels, saved and unsaved places, events) has one header, defined once per list type in `listHeader` (`shared/list-header.ts`, ported to `ListHeaders` in Core and held to it by the vectors). A new list type adds its case there, and both clients follow.

- **Two menus, fixed places.** The filter menu sits at the top left, and the `…` menu at the top right. On the web the filter button sits before the title; on iOS it is the leading bar item, or a glass button at the top left on a tab's root list, with the `…` menu as a glass button at the top right.
- **One order in the `…` menu.** The entries every list shares come first, in this order: `Share`, `Copy as Markdown`, `Show completed`. A separator follows, then the list's own entries: `Newest first`/`Oldest first` (No date), `Add section`, `Rename`, the color, the project icon, `Edit place` (iOS), `Save place`, and the destructive delete last. A new list-specific entry goes in this second group before delete. Each entry shows only where it applies: a shared project or label has no share, rename, or delete, and a saved place has no share, since sharing goes by the tasks carrying a label.
- **Controls that define a view stay visible.** Completed keeps its range picker beside the `…` menu, because the range is what the view shows. No date's sort moved into the menu, since it is a preference, not the content.
- **Filters.** A list filters by who made a task (`Created by`) and by priority (`filterOptions` and `filterTasks` in `shared/list-filters.ts`, ported to `ListFilters`). Each choice shows its count at its right, counted over the list's open rows as the other group filters them, and a choice with no tasks hides unless it is picked. `Created by` shows only when someone other than the user made one of the tasks, and a group with one choice is left out, since it cannot narrow anything. The filter button hides when no group shows and no filter is on. Completed has no filters.
- **Picking.** Turning a group on picks every choice in it, so the user narrows from all by turning choices off. With the group off, picking one choice shows only it. Turning off the last choice turns the group off. A null `createdBy` (a task not synced yet, or an import) counts as the user's.
- **Active state.** The filter icon fills in the accent color while any filter is on. When the filters hide every row, the list reads `No tasks match the filters` with `Clear filters`, instead of its empty state. The menu also ends with `Clear filters` while one is on.
- **Filters persist per list, per device.** Each list keeps its own filter under `filterKey` (`inbox`, `tomorrow`, `this-week`, `no-date`, `project:<id>`, `label:<id>`, `place:<key>`, `event:<id>`), on this device, like `Show completed` and the No date sort. The use case is hiding an AI account's noise in a list day after day, so the filter must survive a relaunch; the filled icon and the filtered empty state keep a forgotten filter from silently hiding tasks. Filters do not sync, since they are a view choice.
- **What a filter touches.** It narrows the open rows, the completed rows shown with `Show completed`, the pending count in the title, and what `Copy as Markdown` copies, so the copy matches the screen. Day headings with no rows left hide; project sections stay, since they are the project's structure.
- **Who made a task.** A row names its creator, `by <name>` with the `AI` badge for an AI account, whenever `createdBy` is someone other than the user, on every list. Both clients ask the server for people they have not met when a task's creator or completer is unknown, the same way they already did for a space's owner.
