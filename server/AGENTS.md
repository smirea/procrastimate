# API server

- `src/api.ts` exports one fetch handler for `/api/*`. `src/index.ts` serves it with Bun in development through `src/dev-server.ts`, and the Cloudflare Worker runs it in production through `src/worker.ts`, which wraps it, the crons, and the `Ramble` Durable Object in Sentry, so keep `api.ts` free of Bun and Node APIs. Sentry stays in `src/sentry.ts`; feature code calls its `span`, `identify`, and `reportError`. Run `bun run start:server` from the root, or `bun run start` here.
- Every HTTP endpoint is a procedure of the oRPC contract in `../shared/api/contract.ts`. Add or change an endpoint there first, then implement it in `src/router.ts`. `bun run start` regenerates the client types as you save. Only Better Auth's routes, sync-engine's `POST /api/sync` and `GET /api/live`, the Ramble WebSocket, the Sentry tunnel, and `PUT /api/images` stay outside the contract. See `docs/decisions/api.md`.
- Every table is in `../shared/db/schema.ts` (`sqlite-core`), and Better Auth's in `src/db/auth-schema.ts`. Every query goes through Drizzle on a `Db` (`src/db/sqlite.ts`): Durable Object SQLite in the `App` object (`src/app-object.ts`), `bun:sqlite` in the Bun server and tests (`src/db/bun-store.ts`). There are no migration files: the engine and `src/db/migrate.ts` add the tables, columns, and indexes the live database lacks on every start, so a schema change is additive (a new name for a retyped column, a default for a new `NOT NULL` one). A Durable Object binds at most 100 parameters per statement and refuses a long compound `SELECT`; the Bun store throws past 100 too, and `src/db/chunks.ts` splits `IN` lists.
- A request's context is the `App` in `src/app.ts`: env, parsed `Config`, the `Store` (Drizzle, the engine's driver, and its space), Better Auth, the sync sockets (`Live`), and in Bun the Ramble route. `src/config.ts` requires `BETTER_AUTH_SECRET` and the VAPID pair; `src/index.ts` fills the local stand-ins env-manager leaves empty. Import settings from generated `src/env.ts` in `src/index.ts` only; the Worker has no env reader. Declare server-only secrets in the server scope of the root `.env`; edit values only in root `.env.local` after `env-manager down`, then `env-manager up`. `scripts/secrets.ts` is the only path from env-manager to Worker secrets, GitHub secrets, and `.dev.vars`; it must never print a value.
- Rows change in one place: the sync-engine hooks in `src/writes.ts`, which a device's sync and the agent API's `space.write` both reach. `admit` decides each write (its space, `guestRefusal` from `shared/scope.ts` for a guest, the authorship stamps), `landed` inserts the `log` rows (with the request's client and op id) and recomputes `access` (`src/access.ts`), the push plan (`src/push.ts`), and the purge only when a write touched what they derive from, and `view` filters each pull to its reader. Derived synced rows go through the engine's `ServerWriter` so they sync. The server never repairs data; readers resolve dangling references with `shared/dangling.ts`. `src/commands.ts` runs the shared store rules on the server over the loaded tree and diffs them into writes, and `src/memo-tasks.ts` writes memo tasks found by source key. `src/space.ts` holds the space's reads: `loadTree` for store rules and views, `loadLinks` (ids and references only) for `scopeOf`, `accessIn` for the caller's standing, and `sightOf`, `seenBy`, and `seesTask` for which rows of each kind the caller sees. `src/people.ts` names people from Better Auth's `user` table. `src/actor.ts` is the only code that reads sessions and `pm.` tokens into an actor, with a one-minute in-memory cache for session bearers.
- `src/api.ts` serves sync (`POST /api/sync`, `GET /api/live`) through the engine's `handleSync` and publishes each new head to `src/live.ts`'s sockets. `src/ramble.ts` is the transcription session, hosted by `src/ramble-object.ts` on the Worker, which reads its data from the `App` object, and by `src/dev-server.ts` in Bun over `src/sockets.ts`; `src/ramble-cassette.ts` is the fake upstream that replays recorded sessions, and `scripts/ramble-latency.ts` measures the real one. Worker bindings are typed in `src/bindings.ts`; `src/worker.ts` forwards `/api/*` to the `App` object.
- Tests run on in-memory SQLite through `src/test-app.ts` and call routes the way clients do; `syncAs` posts the engine's protocol as a device would.
