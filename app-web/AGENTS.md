# Web client

- Svelte 5 (runes) and SvelteKit 3 as a client-only SPA. Routes live in `src/routes/`, shared UI and state in `src/lib/` (imported as `#lib/*`), and Tailwind CSS in `src/index.css`. Domain types and the quick add parser come from `shared/*`.
- SvelteKit config is passed to the `sveltekit()` plugin in `vite.config.ts`; there is no `svelte.config.js`.
- Run `bun run start:client` from the root, or `bun run start` here. Scripts pass `--env-file=.env.local` explicitly because Bun skips env autoloading when it runs Vite through its `node` shim. `env.ts` is the generated Node-side reader for `vite.config.ts`; browser code must not import it.
- `bun run check` runs `svelte-check` with this package's TypeScript 6. `bun run test:e2e` runs the Playwright specs in `e2e/` against a fresh build served by `vite preview` on port 6130, with the browser clock pinned. The `desktop` project runs in Chromium, and the `mobile` project reruns the tests tagged `@webkit` in an iPhone-sized WebKit. Install both once with `bunx playwright install --with-deps chromium webkit`.
- The UI is mobile first. Check every UI change at 393 px wide as well as on desktop, and keep tap targets at 44 px with the `touch:` variant or the `hit-area` class.
- Data lives in the local PowerSync database (`src/lib/database.ts`), which `src/lib/store.svelte.ts` reads into memory and writes through Drizzle; `src/lib/powersync.svelte.ts` connects it. See `docs/decisions/sync.md`.
- Call the API through `api` in `src/lib/api.ts`, which the contract in `shared/api/contract.ts` types. `src/lib/generated/contract.json` is generated by `bun run generate`; never edit it. Only Better Auth's sign-in routes are called with `fetch`.
- Browser API requests use `/api/*`; Vite proxies them unchanged to the root schema's `API_URL`. In production the Worker serves `build/` and `/api/*` on one origin; see `wrangler.jsonc` at the root. The browser only talks to its own origin: never expose an API host or port to browser code, and self-host fonts and assets instead of loading them from a third party.
- Edit schema and values at the repo root. Run `env-manager gen --local` to update child outputs; do not maintain a child `.env` schema or import the env reader into browser code.
