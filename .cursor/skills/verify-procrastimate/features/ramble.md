# Ramble

Ramble lets Stefan talk his tasks in. An empty quick add textbox shows a mic on its right; tapping it swaps quick add for a fullscreen drawer that is already listening. A waveform of the real mic level pulses above the stop button. Tasks rise into the list as they are recognized, with their subtasks and their date, repeat, reminder, priority, project, and label chips, and the end of the transcript shows above the waveform with each recognized phrase tinted. A pill in the header switches between `Smart` (Gemini reads the ramble on the server, corrections and nesting included) and `Commands` (only spoken cues shape it) at any time, and the choice syncs. After stop, and Gemini's last read in smart mode, every title is editable, each task opens its pickers, each task and subtask has a remove button, the mic keeps talking to append more, and `Add N tasks` saves them all. Web and iOS both have it. The design is in `docs/ramble-design.md` and the decisions in `docs/decisions/ramble.md`.

## Sub-features

- `ramble-mic` shows a mic on the right of an empty quick-add textbox. It opens the drawer, listening, with the quick add draft's current defaults: after a save in the open sheet, the last task's project, labels, place, and event (`add-reuse`). The review project chip shows that effective place, section included (`Project Home`, not `Project Inbox`), and a place picked there, `Inbox` too, wins at save. Test: `Ramble from a quick add that stayed open after a save starts in the saved task’s project, and its chip says so` in `e2e/ramble.e2e.ts`. On iOS, launch with `PROCRASTIMATE_DEMO="sections quickadd"` and a script, tap `Ramble`, stop, and tap a title: the chip reads `Project Home`.
- `ramble-wave` draws capsule bars from the real mic level, newest in the middle, rippling outward, settling to dots at rest.
- `ramble-live` adds tasks, subtasks, and field chips as they are recognized, and shows the transcript tail with metadata tinted and spoken commands faded. In smart mode Gemini's outline leads the list once it arrives, and the grammar fills in the words spoken since. Before the first task, three examples for the current mode show.
- `ramble-smart` asks `POST /api/ramble/outline` while the speaker talks, one request at a time, and once more after stop only when the transcript changed since, with `Sorting the ramble…` in the header. Corrections (`actually make that Friday`, `make the dentist one priority one`, `forget the apples`) apply, and listed items nest, two levels deep when the speaker groups them. Offline, without a key (503), or on a failure (502) or a 6 second wait, the grammar's tasks stand.
- `ramble-live-audio` streams the audio to Gemini Live when Dictation is `Gemini Live` (socket `?engine=gemini`). The server sends `outline` messages as the model calls its task tools at each pause, so tasks arrive while speaking without text reads, and corrections and back-references (`make the vet one priority one`) edit earlier tasks. Check it without a microphone: run `bun run start` with `GEMINI_API_KEY` set, then a Playwright Chromium with `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<ramble>.wav%noloop` (a 48 kHz WAV from `say -o x.aiff "…[[slnc 1500]]…"` and `afconvert -f WAVE -d LEI16@48000 -c 1`), sign up, pick `Gemini Live` in Settings, and open Ramble: `outline` frames arrive on the socket after each pause.
- `ramble-mode` is the `Smart` / `Commands` pill (`RambleMode` on iOS). Switching while listening rereads the live list; after stop it rereads the last capture, replacing its tasks. Commands mode splits only on `new task` / `next task`, adds a subtask on `subtask`, notes on `note` or `description` (until the next cue), drops with `scratch that`, and still reads dates, `priority one` to `four`, and existing project and label names.
- `ramble-review` makes every title editable after stop. Tapping a task opens its date, priority, labels, and project pickers, and its repeat and reminders as chips that remove themselves. Each task and subtask has `Remove <title>`. The mic (`Keep talking`) appends a new capture.
- `ramble-save` saves every task with its subtasks (at every depth) and notes from `Add task` or `Add N tasks`, shows the first in its list, and toasts `Added N tasks`. With nothing heard, `Type instead` reopens quick add.
- `ramble-corrections` keeps only the corrected phrase: `Thursday actually make that Friday`, `the 20th, I mean the 21st`, `tomorrow at 3pm sorry 4pm`.
- `ramble-unavailable` explains why the ElevenLabs path is off when its key is missing or the socket is refused. Offline dictation uses the platform recognizer, with no extra banner.
- `ramble-fallback` (web) moves to the ElevenLabs socket when native dictation fails before hearing anything while online, as in Brave, which exposes `SpeechRecognition` but errors at once. A native stop on error or no support shows `Dictation stopped. You can type the task instead.`

## How to get to it (user POV)

- Web and iOS: tap Add, then the mic inside the empty textbox.
- Web keys in the drawer: Escape stops listening, then closes an open editor, then closes the drawer. Space toggles listening and Enter saves when no field has focus.
- iOS: "Start Ramble in ProcrastiMate" from Siri or Shortcuts opens the drawer listening. The DEBUG launch word `PROCRASTIMATE_DEMO=ramble` does the same in the simulator.

## Driving it with control-ui and the simulator

- Native dictation on iOS is `SpeechAnalyzer`, on the device. The simulator has neither a microphone nor the speech model, so use the script below; on a device, a DEBUG build launched from Xcode with the `PROCRASTIMATE_RAMBLE_AUDIO` environment variable set to a spoken audio file streams that file through the real analyzer.
- iOS simulator, which has no microphone: launch with `SIMCTL_CHILD_PROCRASTIMATE_RAMBLE_SCRIPT="<words>"`, tap `Quick add`, then `Ramble`. The script arrives a word at a time, and the waveform moves with a made-up level per word. Say `buy groceries for the party, milk, eggs and bread. Plan the trip to Lisbon, the steps are book flights, find a hotel and rent a car. Oh and call mom tomorrow at 5pm actually make that 6pm`: the list fills live, `Plan the trip to Lisbon` gets three subtasks, and after `Stop listening` it shows `Add 3 tasks` with `Call mom` on `Tomorrow 6pm`. Without taps, launch with `SIMCTL_CHILD_PROCRASTIMATE_INTENTS=ramble` and end the script with `That's all.`: the drawer opens listening and stops on its own. With the dev server holding `GEMINI_API_KEY`, smart mode reads the script through Gemini: `Go to the supermarket at 6pm and there get squid, garlic and some mayo. And then I also need to call the vet tomorrow at 9am, actually make that 10am. That's all.` ends as `Go to the supermarket` (`Today 6pm`) with `Squid`, `Garlic`, `Mayo`, and `Call the vet` (`Tomorrow 10am`). A failed request logs `Ramble outline failed` under the `errors` category and keeps the grammar's tasks. Tap `RambleMode` to switch to commands and back. Say `call the dentist tomorrow at 3pm sorry 4pm priority 2`: the drawer shows `Call the dentist` with `Tomorrow 4pm` and `P2`.

- On a paired device, open the drawer and say "Call mom tomorrow at 5pm priority one." The bars move with your voice, `Call mom` arrives with `Tomorrow 5pm` and `P1` chips. Stop, then `Add task` saves that one task.
- Say "Finish the project report" with no project named `report`. The task keeps that title and no extra chips.
- Every space's names, as in quick add. On iOS, launch with `PROCRASTIMATE_DEMO=sharing`, `PROCRASTIMATE_INTENTS=ramble`, and the script `Water the tulips in project Garden. Next task, try the soup in project Recipes.`: `Water the tulips` gets `Garden` (Ann's, shared to edit), while `Recipes` (view only) stays in the second title. The second task's project picker lists `Garden` and not `Recipes`; picking `Garden` and `Add 2 tasks` puts both in Ann's Garden. On the web, `ramble.e2e.ts` shares one project to edit and another to view, and the rambled task picked into the first shows up on the owner's device.
- With Dictation set to ElevenLabs and no key, or a refused socket, the drawer says Ramble needs a connection. Offline, or Dictation set to Native, uses the platform recognizer and does not open the socket.
- In Brave online with Dictation set to Native, tap the mic. Recognition fails at once and capture moves to the ElevenLabs socket, so the mic keeps listening.
- On iOS, tap just beside the mic glyph. The mic's whole rectangle is its hit area and the card has a content shape, so the tap opens the drawer instead of reaching the scrim.
- Web: `app-web/e2e/ramble.e2e.ts` grants a fake microphone, names the `party` cassette on the socket URL, and drives streaming, editing, removing, saving, and Escape. The fake mic's beep drives the bars. A third test routes `/api/ramble/outline` to a fixed outline with a nested subtask and switches modes after stop. The cassette replays against audio frames, and headless Chrome on macOS sends none, so these run on CI's Linux runner.

## Parser

`parseRamble` in `shared/ramble.ts` turns a transcript into tasks, with `commands: true` for commands mode. `outlineRamble` in `server/src/ramble-outline.ts` holds the Gemini prompt and schema, and `resolveOutline` in `shared/ramble.ts` (Swift `Ramble.resolveOutline`) turns its outline into tasks, phrases through quick add and names to ids. The live request loop is `Outliner` in `app-web/src/lib/ramble/outliner.ts` and `RambleOutliner` on iOS. `Ramble.newTask` (`Core/RambleNewTask.swift`) saves a spoken task with the list defaults. `server/scripts/ramble-eval.ts` scores the grammar and Gemini models on the labelled rambles in `shared/fixtures/ramble-eval/`. `rambleNewTask` in `shared/ramble-fill.ts` is the web's `Ramble.newTask`. The drawer keys parsed tasks by position (`keyed` in `app-web/src/lib/ramble/entries.ts`, `RambleEntry.keyed` in Swift) so rows survive reparsing. The corpus is in `shared/ramble.test.ts`; locked cases are recorded in `shared/vectors/ramble.json`. The Swift port is `Core/Ramble.swift`. Linux `VectorTests` runs the grammar cases. Spoken mode is in the Swift quick add parser.

## Gotchas

- ElevenLabs needs the network and the key. Native dictation is the platform recognizer and works offline. The grammar is local. The choice syncs with the other settings.
- The transcription socket is `GET /api/ramble/socket` on a signed-in device. The web sends the session cookie and `device.<id>` as a subprotocol, like sync. iOS sends `Authorization: Bearer`, the `procrastimate.ramble` subprotocol, and `x-procrastimate-device`.
- Two cassettes exist: `three-tasks` (the default) and `party` (a list with subtasks, a time, a priority, and a reminder). "That's all" stops listening and does not save. Closing the drawer discards the ramble.
- `TZ=UTC GEMINI_API_KEY=… bun server/scripts/ramble-eval.ts -v --with grammar,gemini:gemini-3.5-flash-lite:minimal shared/fixtures/ramble-eval/todoist-dev.json` scores parsers (`-v` prints each miss). Tune on `dev`, `structure`, and `todoist-dev`; run `holdout` and `todoist-holdout` once at the end. On Gemini's free tier pass `--gap 4000`, and read latency from the median, since free-tier queueing adds seconds to the tail.
- `Evals/LabelColorModel` beside it scores the label color model the same way: `bun run generate`, then `swift run -c release eval -v cases.json default model` from that folder, against 32 names that each accept one or more colors. See the labels feature.
- App Shortcuts keep ten phrases. Start Ramble took the slot Delete All Data had. The delete intent is still there.
